## 量化系统调试的第一性原理

### 传统软件 vs 量化系统

| 维度 | 传统软件 | 量化系统 |
|------|---------|---------|
| 正确性 | 输出对/错（二值） | 输出有概率分布（连续） |
| 失败模式 | 崩溃/报错 | 静默亏钱（更危险） |
| 调试方法 | 复现bug、加断点 | 对比回测vs实盘、分解归因 |
| 时间尺度 | 毫秒~秒 | 天~月（衰减很慢） |

**核心区别：量化系统的错误往往是"沉默的"——不报错，但慢慢亏钱。**

### 调试的第一性原则

1. **先分清是"代码错了"还是"逻辑错了"**
   - 代码错了：程序行为和你想的不一样
   - 逻辑错了：程序行为和你想的一样，但策略本身不赚钱

2. **先复现，再诊断**
   - 没有稳定复现的问题，不要动手改
   - 能用回测复现的，不要去实盘试

3. **每次只改一个变量**
   - 改了A又改B，出了问题不知道是谁的锅

## 问题分层诊断框架

### 五层诊断法

当策略表现异常时，从下往上逐层排查：

```
Layer 5: 市场层    —— 市场结构变了吗？策略失效了吗？
Layer 4: 执行层    —— 滑点、延迟、成交质量比预期差吗？
Layer 3: 风控层    —— 止损、仓位、回撤控制按预期执行了吗？
Layer 2: 信号层    —— 信号生成逻辑正确吗？有前视偏差吗？
Layer 1: 数据层    —— 数据质量对吗？时间对齐了吗？
```

**排查顺序：从下往上（Layer 1 → Layer 5）。**
原因：底层问题最容易验证，也最常见。

## 策略表现异常的诊断流程

### Step 1：数据层检查（最常见的问题）

**检查清单：**
- [ ] 数据时间戳对齐了吗？（日线/小时线/分钟线时区一致吗？）
- [ ] 有没有缺失值？（节假日、跳空、数据断档）
- [ ] 有没有异常值？（价格跳变、成交量为0的bar）
- [ ] 复权了吗？（前复权/后复权一致吗？）
- [ ] 幸存者偏差？（退市股票算了吗？）

**快速验证：**
```python
# 检查数据质量
df.isnull().sum()           # 缺失值
df.describe()                # 异常值
df['close'].pct_change().describe()  # 日收益率分布
```

### Step 2：信号层检查（前视偏差重灾区）

**检查清单：**
- [ ] 信号 shift 了吗？（当天收盘价算的信号，当天交易了吗？）
- [ ] 标准化参数用的全样本还是滚动窗口？
- [ ] 特征计算有没有用未来数据？
- [ ] 回测和实盘的信号一致吗？（同一天同一个品种，信号一样吗？）

**快速验证：特征滞后测试**
```python
# 把信号 shift 一天，看收益变化大不大
df['signal_shifted'] = df['signal'].shift(1)
# 如果 shift 后收益暴跌 → 很可能有前视偏差
```

### Step 3：风控层检查

**检查清单：**
- [ ] 止损按预期执行了吗？（该止损的时候止损了吗？）
- [ ] 仓位计算正确吗？（风险预算对吗？）
- [ ] 回撤控制触发了吗？（到了回撤阈值减仓了吗？）
- [ ] 极端情况处理了吗？（跳空、流动性消失）

**快速验证：**
```python
# 对比理论止损价 vs 实际成交价
# 差距大吗？差距大说明滑点严重
```

### Step 4：执行层检查

**检查清单：**
- [ ] 滑点比预期大吗？（回测假设的滑点 vs 实际滑点）
- [ ] 延迟有多少？（信号产生到下单的时间差）
- [ ] 成交率如何？（挂单成交了吗？）
- [ ] 大单的市场冲击？（你的单子推动了价格吗？）

**快速验证：**
```python
# 计算实际滑点
slippage = actual_fill_price - expected_price
# 统计平均滑点、最大滑点
```

### Step 5：市场层检查（策略失效）

**检查清单：**
- [ ] 市场状态变了吗？（趋势市变震荡市了？）
- [ ] 策略拥挤了吗？（大家都在做，收益衰减了？）
- [ ] 宏观环境变了吗？（利率、政策、地缘政治）
- [ ] Alpha 衰减了吗？（IC 连续下降？）

**快速验证：**
```python
# 滚动 IC（信息系数）
rolling_ic = df['signal'].rolling(60).corr(df['forward_return'])
# IC 连续下降 → Alpha 在衰减
```

## 系统性能优化

### 性能优化的第一性原理

**不要为了优化而优化。先 profile，找到瓶颈，再优化。**

```
优化前：测一下，找到瓶颈在哪
优化中：每次只改一个变量，测一下效果
优化后：确认没有引入新问题
```

### 回测速度优化

**常见瓶颈：**

| 瓶颈 | 占比 | 优化方法 |
|------|------|---------|
| 循环（for loop） | 70% | 向量化（numpy/pandas） |
| 数据加载 | 15% | 预加载、缓存 |
| 特征计算 | 10% | 预计算、增量计算 |
| 其他 | 5% | - |

**优化技巧：**

1. **向量化优先**
   ```python
   # ❌ 慢：循环
   for i in range(len(df)):
       df.loc[i, 'ma'] = df['close'].iloc[i-20:i].mean()
   
   # ✅ 快：向量化
   df['ma'] = df['close'].rolling(20).mean()
   ```

2. **预计算特征**
   - 把所有特征先算好，存成 DataFrame
   - 回测的时候直接查表，不要边算边跑

3. **减少不必要的拷贝**
   - pandas 的 `.copy()` 很耗内存
   - 尽量原地操作（注意 settingWithCopyWarning）

4. **用更高效的数据结构**
   - 大数据用 parquet 代替 csv
   - 数值计算用 numpy 代替纯 Python

### 内存优化

**常见问题：**
- 全量数据加载到内存
- 中间变量没释放
- pandas 的 dtype 太大

**优化方法：**
```python
# 指定 dtype，减少内存
df = pd.read_csv('data.csv', dtype={'close': 'float32', 'volume': 'int32'})

# 只加载需要的列
df = pd.read_csv('data.csv', usecols=['timestamp', 'close', 'volume'])

# 及时释放不用的变量
del df_large
import gc; gc.collect()
```

## 执行延迟优化

### 延迟的组成

```
总延迟 = 信号计算时间 + 网络传输时间 + 经纪商处理时间 + 成交时间
```

| 环节 | 典型延迟 | 优化方向 |
|------|---------|---------|
| 信号计算 | 1-10ms | 优化代码、预计算 |
| 网络传输 | 1-50ms | co-location、就近机房 |
| 经纪商处理 | 10-100ms | 选低延迟经纪商 |
| 成交确认 | 10-100ms | - |

### 什么场景需要优化延迟

**不需要优化的场景：**
- 日线级别的策略（一天交易一次）
- 中低频趋势跟踪

**需要优化的场景：**
- 高频做市
- 事件驱动新闻交易
- 对延迟敏感的套利策略

### 优化原则

**对于中低频策略：先保证正确性，再优化速度。**
**不要为了省 10ms，引入前视偏差。**

## 调试工具与技巧

### 必备工具

1. **日志系统**
   - 每笔交易的完整决策过程
   - 时间戳、价格、信号、仓位、风控调整

2. **回测对比工具**
   - 同一策略、同一数据，回测和实盘的对比
   - 信号差异、成交价差异、仓位差异

3. **性能分析工具**
   - Python: `cProfile`、`line_profiler`
   - 内存: `memory_profiler`

4. **可视化工具**
   - 收益曲线对比
   - 回撤分析
   - 滚动 IC、滚动 Sharpe

### 调试技巧

#### 技巧1：最小复现
- 不要在完整策略里找bug
- 写一个最小的测试用例，只复现问题
- 找到问题后再修复

#### 技巧2：二分法
- 不知道问题在哪？
- 把数据分成两半，看哪一半有问题
- 继续分，直到找到具体位置

#### 技巧3：黄金集测试
- 准备一组"黄金数据"——已知正确答案的测试用例
- 每次改完代码，跑一遍黄金集
- 黄金集过了，说明没有引入新bug

#### 技巧4：因果性自动检测
- 每次写完新代码，自动跑前视偏差检测
- 特征 shift 一天，看收益变化大不大

## 常见问题速查表

| 现象 | 可能原因 | 排查方向 |
|------|---------|---------|
| 回测赚钱，实盘亏钱 | 前视偏差、过拟合、滑点 | 信号层、数据层 |
| 策略最近表现突然变差 | 市场状态变化、Alpha衰减 | 市场层、IC监控 |
| 回撤比预期大很多 | 滑点严重、跳空、风控失效 | 执行层、风控层 |
| 回测速度太慢 | 循环、数据量大、特征计算慢 | profile找瓶颈 |
| 内存爆了 | 全量加载、中间变量没释放 | 内存分析工具 |
| 信号不一致（回测vs实盘） | 时间戳对齐、数据版本不同 | 数据层、信号层 |
| 止损没触发 | 跳空、流动性消失、代码bug | 执行层、风控层 |
| 成交率很低 | 挂单价格不对、流动性差 | 执行层 |

## 顶级机构怎么做

### Two Sigma
- 全链路监控：每个环节都有指标
- 自动化告警：异常自动发现
- 严格的回测-实盘一致性验证

### Renaissance
- 海量弱信号叠加，单个信号失效影响不大
- 自动退役机制：信号衰减到阈值以下自动下线
- 严格的过拟合检测

### 共同原则
- **监控一切**：没有监控就无法诊断
- **自动化优先**：能自动检测的不要人工查
- **先分清是代码错了还是逻辑错了**——这是第一步
