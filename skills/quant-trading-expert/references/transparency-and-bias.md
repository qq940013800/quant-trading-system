## 前视偏差（未来函数）是什么

### 第一性原理

**前视偏差（Look-Ahead Bias）= 用了未来才知道的信息做过去的决策。**

这是量化交易最隐蔽、最致命的错误——回测看起来完美，实盘亏到爆。

**类比：**
> 你考完试，拿到答案了，再回去"考"一次。当然满分。
> 但这不是你的真实水平，是作弊。

### 为什么它最危险

1. **隐蔽**：代码看起来没问题，但就是偷偷用了未来信息
2. **致命**：回测 Sharpe 3.0，实盘 Sharpe -0.5
3. **难查**：一个小函数的一行代码，就能引入前视偏差

## 常见前视偏差陷阱

### 陷阱1：用收盘价计算指标，再用同一天收盘价交易

```python
# ❌ 错误示例
df['ma20'] = df['close'].rolling(20).mean()
df['signal'] = np.where(df['close'] > df['ma20'], 1, -1)
# 问题：你在 t 时刻用了 t 时刻的收盘价算指标，
# 然后用 t 时刻的收盘价交易——
# 但 t 时刻的收盘价是收盘后才知道的！
```

**正确做法：**
```python
# ✅ 正确：信号 shift 一天
df['ma20'] = df['close'].rolling(20).mean()
df['signal'] = np.where(df['close'] > df['ma20'], 1, -1).shift(1)
# t 时刻的信号，用的是 t-1 时刻及之前的数据
```

### 陷阱2：未来函数的均值/标准差

```python
# ❌ 错误：用全样本计算标准化参数
df['zscore'] = (df['close'] - df['close'].mean()) / df['close'].std()
# 问题：mean() 和 std() 用了整段数据（包括未来）
```

**正确做法：**
```python
# ✅ 正确：用滚动窗口
df['mean'] = df['close'].rolling(20).mean()
df['std'] = df['close'].rolling(20).std()
df['zscore'] = (df['close'] - df['mean']) / df['std']
# 每个点只用过去20天的数据
```

### 陷阱3：幸存者偏差

```python
# ❌ 错误：只选现在还活着的股票
# 问题：已经退市的股票你没算进去
# 那些退市的股票大多是跌了90%以上的
# 去掉它们，回测收益自然就高了
```

### 陷阱4：点差和滑点的"未来信息"

```python
# ❌ 错误：你以为你能在收盘价成交
# 实际：收盘价是收盘那一刻的价格
# 你下单到成交有延迟，价格已经动了
```

### 陷阱5：财报数据的时间差

```python
# ❌ 错误：用 t 季度的财报数据，在 t 季度初就交易
# 问题：财报是季度结束后才发布的
# 你在季度初不可能知道季度末的财报数据
```

## 前视偏差自动检测

### 检测方法1：时间戳对齐检查

**规则：** 任何特征或信号的计算，只能使用 `timestamp <= bar.close_time` 的数据。

**实现方式：**
```python
# 用 @as_of 装饰器强制检查
def get_feature(as_of_time: datetime) -> float:
    # 只查 as_of_time 及之前的数据
    data = query_data(as_of=as_of_time)
    return compute_feature(data)
```

### 检测方法2：特征滞后测试

**方法：** 把特征故意 shift 一天，看回测结果变化大不大。

- 如果 shift 一天后收益暴跌 → 原策略很可能有前视偏差
- 如果 shift 一天后收益差不多 → 策略比较稳健

### 检测方法3：样本内/样本外对比

**方法：** 把数据分成两段，前一段训练，后一段测试。

- 如果样本内 Sharpe 2.0，样本外 Sharpe 0.2 → 很可能有前视偏差（或过拟合）
- 如果两者差不多 → 策略比较真实

## 决策可解释性原则

### 为什么需要可解释性

1. **出了问题能查**：为什么这笔交易亏了？是信号错了，还是风控漏了？
2. **能迭代改进**：知道哪里好、哪里不好，才能针对性优化
3. **能建立信任**：你敢把真金白银交给一个你完全不懂的黑箱吗？
4. **符合监管要求**：越来越多监管要求算法交易可解释

### 可解释性的层级

```
Level 0：完全黑箱——你不知道它为什么做这个决策
Level 1：特征重要度——知道哪些特征贡献大
Level 2：决策规则——知道大致的决策逻辑
Level 3：完整审计——每笔交易的每一步都能还原
```

**目标：至少达到 Level 2，最好达到 Level 3。**

## 避免黑箱：模型可解释性

### 原则1：从简单开始

**奥卡姆剃刀：如无必要，勿增实体。**

- 3 行规则能赚钱，就不要用 100 行的深度神经网络
- 逻辑回归能解释清楚，就不要用随机森林
- 简单的策略：你知道它什么时候会失效
- 复杂的模型：你自己都不知道它在做什么

### 原则2：特征重要度

**任何模型，都要输出特征重要度：**

- 这个决策主要是哪个特征驱动的？
- 是趋势指标？还是波动率？还是成交量？
- 如果最重要的特征失效了，策略会怎么样？

### 原则3：局部解释

**对于每笔具体的交易，要能解释：**

- 为什么做多？（哪几个条件触发了？）
- 为什么止损设在这里？（基于什么？）
- 为什么仓位是这么多？（风险预算怎么算的？）

### 原则4：模型选择的可解释性阶梯

```
可解释性高 ←────────────────────→ 预测能力强

规则/决策树 → 线性回归 → GBDT → 随机森林 → 神经网络
```

**选择建议：**
- 逻辑清晰、需要强可解释性 → 规则/线性模型
- 有大量弱信号、可接受一定黑箱 → GBDT
- 数据量极大、不差钱不差算力 → 深度学习（慎用）

## 决策审计日志系统

### 什么是决策审计日志

**每一笔交易的完整决策过程，都要记录下来：**

1. 当时的市场状态是什么？
2. 输入了哪些特征？值是多少？
3. 模型/规则输出了什么信号？
4. 风控做了什么调整？
5. 最终下单了多少？为什么？

### 记录的核心字段

```python
@dataclass
class DecisionAudit:
    timestamp: datetime           # 决策时间
    strategy_id: str              # 哪个策略
    strategy_version: str          # 哪个版本
    # 输入
    market_state: dict            # 市场状态（趋势/震荡/波动率）
    features: dict                # 所有特征值（完整快照）
    # 信号
    raw_signal: float             # 原始信号
    signal_strength: float        # 信号强度
    signal_confidence: float      # 信号置信度
    # 风控调整
    risk_adjustments: list        # 风控做了哪些调整
    final_position: float         # 最终仓位
    # 原因
    reasoning: str                # 人类可读的决策理由
```

### 为什么重要

**案例：** 策略连续亏了 5 笔，你想知道为什么？
- 没有审计日志：不知道哪里错了，只能瞎猜
- 有审计日志：一看，哦，是市场状态判断错了，本来是震荡市，策略当成趋势市了

## 透明度检查清单

### 前视偏差检查

- [ ] 所有特征都只用 `timestamp <= bar.close` 的数据吗？
- [ ] 信号是不是 shift 了一天？
- [ ] 标准化参数是滚动计算的，还是用了全样本？
- [ ] 有没有幸存者偏差？（退市股票算了吗？）
- [ ] 财报数据的时间差考虑了吗？
- [ ] 做过特征滞后测试吗？（shift 一天，收益变化大不大？）

### 可解释性检查

- [ ] 我能说清楚这个策略的逻辑吗？（不是"回测好看"）
- [ ] 这个策略赚的是什么钱？（Alpha 来源是什么？）
- [ ] 这个策略什么时候会失效？
- [ ] 模型有特征重要度吗？
- [ ] 每笔交易都能还原决策过程吗？
- [ ] 出了问题，我能定位是哪个环节错了吗？

### 审计日志检查

- [ ] 每笔交易都有完整的决策记录吗？
- [ ] 记录了所有输入特征的值吗？
- [ ] 记录了风控调整的过程吗？
- [ ] 有人类可读的决策理由吗？
- [ ] 能按策略、按时间、按结果查询吗？

## 顶级机构怎么做

### Renaissance Technologies
- 他们的策略极度复杂，但内部有完整的可解释性体系
- 每一个信号都有人负责，知道为什么有效、什么时候会失效
- 不是"黑箱"，是"很多人都理解的复杂系统"

### Two Sigma
- 严格的实验管理：每个实验都完整记录
- 模型上线前必须通过可解释性审查
- 自动生成决策解释报告

### 共同原则
- **复杂不等于黑箱**——复杂但每一步都可解释
- **可解释性不是奢侈品，是必需品**
- **你敢不敢把真金白银交给它？不敢的话，就不要上线**

## 实战建议

### 第一步：先做最简单的版本

不要一开始就上深度学习。先用规则/线性模型，把整个系统跑通。

### 第二步：建立审计日志

从第一天开始，每笔交易都记录完整决策过程。

### 第三步：做前视偏差扫描

每次写完新代码，自动跑一遍前视偏差检测。

### 第四步：定期做可解释性审查

每隔一段时间，拿几笔交易出来，问问自己：
- 为什么做多？
- 为什么仓位是这么多？
- 为什么止损设在这里？

答不上来，就说明这个策略太黑箱了，需要简化。
