## 为什么需要可解释性

### 黑箱模型的危险

一个准确率90%的ML模型，你不知道：
1. 它为什么做这个决策？
2. 它什么时候会错？
3. 它是真的学到了规律，还是记住了噪声？
4. 市场变了，它怎么知道自己失效了？

**黑箱模型在回测里可能表现很好，但实盘突然崩了——你都不知道为什么。**

### 可解释性的价值

1. **信任**——你知道模型为什么做这个决策，才敢用真钱跑
2. **调试**——模型出错时，你知道是哪个特征出了问题
3. **改进**——你知道哪些特征有用，哪些没用，才能改进
4. **合规**——监管要求金融决策可解释
5. **风险管理**——你知道模型在什么情况下会失效，才能提前防范

## 可解释性阶梯

从最简单到最复杂：

```
Level 0: 黑箱模型
    你完全不知道模型在做什么
    
Level 1: 可解释模型
    线性回归、决策树——模型本身就是可解释的
    
Level 2: 事后解释
    用SHAP/LIME等工具解释黑箱模型的决策
    
Level 3: 内在可解释模型
    专门设计的可解释ML模型（如EBM）
    
Level 4: 决策完全透明
    每一步决策都有明确的输入、规则、输出，
    任何人都能复盘还原
```

### 量化交易的建议

**目标：Level 4——决策完全透明。**

交易系统的每一笔交易都应该能回答：
- 为什么开仓？（输入了什么数据？用了什么规则？）
- 为什么这个仓位？（怎么算出来的？）
- 为什么这个止损？（依据是什么？）
- 为什么平仓？（触发了什么条件？）

## 全局解释 vs 局部解释

### 全局解释

**问题：这个模型整体是怎么工作的？**

- 哪些特征最重要？
- 特征和目标的关系是什么？（正相关还是负相关？）
- 模型的整体逻辑是什么？

### 局部解释

**问题：这个具体的决策，模型为什么这么做？**

- 这一笔交易，为什么开多不开空？
- 这个信号强度0.8，是哪些因素推上去的？
- 这个止损设在1995，是怎么算出来的？

### 两者都需要

- 全局解释：理解模型，改进模型
- 局部解释：审计每笔交易，出问题时能定位

## 常用解释工具

### 1. 特征重要性（全局）

最简单的解释：哪些特征对模型最重要？

| 方法 | 优点 | 缺点 |
|------|------|------|
| 随机森林特征重要性 | 快，直观 | 偏向高基数特征 |
| 排列重要性 | 无偏，模型无关 | 计算慢 |
| SHAP值 | 最准确，有理论基础 | 计算慢 |

### 2. SHAP值（全局+局部）

**原理：** 把每个特征的贡献分解出来——就像博弈论里的Shapley值。

**输出：**
- 全局：每个特征对模型的整体贡献
- 局部：每一个预测，每个特征贡献了多少

**例子：**
模型预测"涨"，SHAP分解：
- ATR高 → 推高信号 +0.3
- 市场结构 bullish → 推高信号 +0.5
- 成交量低 → 拉低信号 -0.1
- 其他 → 0.1
- 总和 = 0.8（预测值）

### 3. 部分依赖图（PDP）

**问题：** 某个特征变化时，模型预测会怎么变？

**例子：**
- ATR从1涨到5，模型预测的信号强度怎么变？
- 是线性的？还是有拐点？

### 4. LIME（局部解释）

**原理：** 在单个预测附近拟合一个简单的可解释模型。

**优点：** 模型无关，任何黑箱都能解释。
**缺点：** 只是近似，不一定准确。

## 决策审计日志

### 什么是决策审计日志

每一笔交易决策，都完整记录：
1. **输入**——当时用了什么数据？什么特征？
2. **规则**——用了什么策略？什么参数？
3. **输出**——最终做了什么决策？
4. **原因**——为什么做这个决策？

### 为什么重要

**硬规则：决策可审计——每笔接受/拒绝都能还原各层输入与判断。**

出问题时，你能完整复盘：
- 当时数据是什么？
- 特征算出来是多少？
- 信号强度是多少？
- 风控怎么判断的？
- 最后为什么下单/不下单？

### 日志应该记录什么

```json
{
  "timestamp": "2024-01-15T10:30:00",
  "strategy": "ml_trend_v1",
  "inputs": {
    "close": 2000.5,
    "atr": 2.3,
    "structure": "bullish_breakout",
    "rsi": 55
  },
  "features": {
    "trend_strength": 0.75,
    "volatility_regime": "normal",
    "signal_raw": 0.65
  },
  "decision": {
    "action": "GO_LONG",
    "signal_strength": 0.8,
    "stop_loss": 1995.0,
    "target_lot": 0.1
  },
  "reason": "ATR正常，市场结构突破，RSI不超买"
}
```

## 模型监控与漂移检测

### 为什么要监控模型

**模型上线即衰减。**

市场是变化的——策略的逻辑可能慢慢失效。

你不能等亏钱了才发现模型不行了。

### 监控什么

#### 1. 数据漂移

输入数据的分布变了——模型见都没见过这种数据。

**检测：** 监控特征的分布（均值、方差、分位数），和训练时对比。

#### 2. 概念漂移

特征和目标的关系变了——以前有用的特征，现在没用了。

**检测：** 监控模型预测的准确率、Sharpe、胜率，和训练时对比。

#### 3. 决策质量监控

模型最近的决策质量怎么样？

**指标：**
- 预测的信号强度 vs 实际胜率
- 预测的盈亏比 vs 实际盈亏比
- 最近的回撤是否超过历史范围

### 告警机制

| 指标 | 告警阈值 | 动作 |
|------|---------|------|
| Sharpe下降 | 连续30天Sharpe < 历史均值的50% | 警告 |
| 最大回撤 | 超过历史最大回撤的1.5倍 | 减仓 |
| 胜率下降 | 连续20笔交易胜率 < 历史胜率的60% | 暂停 |
| 数据漂移 | 特征分布偏移超过阈值 | 检查数据 |

## 常见陷阱

### 1. 可解释性 = 不重要

"模型准确率高就行了，管它怎么工作的。"

**错。** 黑箱模型在你不知道的地方崩了。

### 2. 用线性模型就等于可解释

线性模型是可解释的，但如果特征本身是一堆复杂的工程，那还是黑箱。

### 3. SHAP值=可解释

SHAP是工具，不是目的。你用SHAP发现特征A最重要，但你不知道为什么特征A重要。

### 4. 只做全局解释，不做局部解释

全局解释告诉你模型整体怎么工作，但具体某一笔交易为什么这么做，你不知道。

### 5. 模型上线就不管了

模型会衰减，市场会变。不监控=等死。
