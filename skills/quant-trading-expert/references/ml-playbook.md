## ML 在量化中的正确定位

### ML 擅长什么

✅ **从大量弱信号中提取模式**：几百个特征，每个都很弱，ML 能找到它们的组合方式。
✅ **非线性关系建模**：特征之间的交互效应、阈值效应。
✅ **特征选择**：自动告诉你哪些特征重要，哪些是噪声。
✅ **动态权重调整**：市场状态变化时，自动调整模型参数。

### ML 不擅长什么

❌ **预测强趋势或拐点**：趋势是人的行为和宏观驱动的，不是数据模式能预测的。
❌ **小样本学习**：金融数据样本少、噪声大，深度学习很容易过拟合。
❌ **因果推断**：ML 找到的是相关性，不是因果性。
❌ **可解释性**：黑箱模型出了问题你都不知道为什么。
❌ **预测极端事件**：黑天鹅是罕见事件，数据里根本没有足够样本。

### 正确的 ML 工作流

```
原始数据 → 特征工程 → 基础信号（规则/统计）→ ML 做 meta-labeling → 组合信号 → 仓位管理 → 执行
```

**核心原则**：ML 不应该是你的第一选择。先用简单的规则方法建立 baseline，再用 ML 去优化和提升。

## 模型选择决策树

```
开始
  │
  ├─ 样本量 < 1000？
  │    └─ 是 → 逻辑回归 / 简单规则模型（不要用复杂模型）
  │
  ├─ 需要强可解释性？
  │    └─ 是 → 线性模型 / GBDT（带特征重要性）
  │
  ├─ 特征数量 > 50 且很多弱特征？
  │    ├─ 是 → GBDT (LightGBM/XGBoost)
  │    └─ 否 → 逻辑回归 / SVM
  │
  ├─ 时序数据且有长程依赖？
  │    ├─ 是 → Transformer / TCN（小心过拟合）
  │    └─ 否 → GBDT
  │
  ├─ 需要做市/实时决策？
  │    └─ 是 → 逻辑回归 / 浅层 GBDT（速度快、稳定）
  │
  └─ 其他情况 → 从简单模型开始，逐步复杂化
```

### 各模型的适用场景

| 模型 | 优点 | 缺点 | 适用场景 |
|------|------|------|---------|
| **逻辑回归** | 简单、稳定、可解释 | 只能线性 | baseline、快速验证 |
| **GBDT (LightGBM/XGBoost)** | 处理非线性、特征交互、鲁棒 | 容易过拟合、需调参 | 特征工程后的主要模型 |
| **随机森林** | 抗过拟合、鲁棒 | 精度不如 GBDT | 快速原型、特征重要性 |
| **SVM** | 小样本、高维有效 | 慢、难调参 | 小数据集 |
| **神经网络 (MLP)** | 拟合复杂非线性 | 极易过拟合、需大量数据 | 大样本、特征丰富 |
| **Transformer** | 长程依赖、序列建模 | 极度过拟合、数据饥渴 | 大规模时序数据 |
| **强化学习 (RL)** | 端到端优化、适应环境 | 不稳定、难调参、样本效率低 | 做市、执行优化（不是方向预测） |

## 标签工程

### 标签比模型更重要

**垃圾标签进 = 垃圾模型出。** 标签定义错了，再牛的模型也白搭。

### 常见标签类型

#### 1. 固定时间收益标签
```
y = return(t, t + h)
```
- 优点：简单直接
- 缺点：没有考虑路径——中途可能暴跌又回来，你扛不住
- 适用：快速 baseline

#### 2. 三重障碍标签（推荐）
```
上轨止盈 / 下轨止损 / 时间到期
```
- 标签 = 哪个障碍先被触发
- 优点：符合真实交易逻辑，考虑了路径
- 缺点：需要设定障碍宽度（通常用 ATR 倍数）
- 适用：大多数策略

#### 3. 元标签 (Meta-Label)
```
第一步：用基础模型生成信号（买/卖/持有）
第二步：用 ML 预测这个信号的成功率
第三步：根据预测成功率调整仓位
```
- 优点：不改变原始信号，只优化仓位
- 缺点：需要先有一个不错的基础信号
- 适用：成熟策略的精细化优化

### 标签工程原则

1. **标签必须和交易逻辑一致**：你怎么交易，就怎么定义标签。
2. **考虑交易成本**：标签里要扣掉手续费和滑点。
3. **不平衡标签要处理**：大多数时候应该是"持有"，买/卖是少数。
4. **不要泄露未来信息**：标签是未来的，但特征必须是过去的。

## 特征工程原则

### 特征质量 > 特征数量

10 个高质量特征 > 1000 个噪声特征。

### 好特征的标准

- **有经济学/金融学逻辑**：不是纯数据挖掘出来的伪规律。
- **稳定**：在不同时间段、不同市场环境下都有效。
- **低相关**：和已有特征不要太像。
- **可解释**：出了问题你能解释为什么。

### 常见特征类别

| 类别 | 例子 | 注意事项 |
|------|------|---------|
| **价格/成交量** | RSI、MACD、布林带、换手率 | 最基础，也最容易过拟合 |
| **波动率** | ATR、历史波动率、已实现波动率 | 波动率聚集是稳定的现象 |
| **动量/反转** | N 日收益率、52 周高低点距离 | 注意时间尺度匹配 |
| **趋势** | 均线斜率、ADX、Hurst 指数 | 趋势识别要滞后，不要太敏感 |
| **相对价值** | 相对强弱、配对价差 | 需要协整性检验 |
| **流动性** | 买卖价差、订单簿深度 | 高频数据才有 |
| **基本面** | PE、PB、ROE、盈利增速 | 低频，适合中长线 |
| **另类数据** | 舆情、卫星、信用卡 | 数据获取成本高，小心幸存者偏差 |
| **微观结构** | 订单流失衡、成交量分布 | 高频做市用 |

### 特征工程禁忌

- ❌ **用未来数据计算特征**：移动平均不能用未来的值填充。
- ❌ **在全样本上做标准化**：应该只用训练集的均值方差来标准化。
- ❌ **太多相似特征**：10 个不同周期的 RSI 本质上是一个特征。
- ❌ **过拟合特征**：在样本上调整到完美的特征，样本外就废了。

## 过拟合防御三件套

### 为什么需要三件套

单靠 train/test split 远远不够。金融数据噪声大、样本少、多重检验问题严重，你必须用更严格的方法。

### 1. CPCV (Combinatorial Purged Cross-Validation)

**传统 K 折交叉验证的问题**：
- 数据泄露——训练集和测试集有重叠的信息
- 只做一次拆分，结果有偶然性

**CPCV 的做法**：
1. 把数据分成 N 组
2. 每次选 k 组做测试集，其余做训练集
3. 组合数 = C(N, k)，重复很多次
4. 每次都做 purging（去掉训练集中和测试集时间相邻的数据点）
5. 综合所有拆分的结果

**效果**：更严格、更可靠的样本外估计。

### 2. PBO (Probability of Backtest Overfitting)

**定义**：在回测中表现最好的策略，在样本外表现不如中位数的概率。

**怎么算**：
1. 用 CPCV 生成很多个 train/test 组合
2. 在每个训练集上选表现最好的策略
3. 看这个策略在对应测试集上的排名
4. 如果很多时候它在测试集上排名很差，说明你过拟合了

**判断标准**：
- PBO < 20%：可以接受
- PBO 20-40%：需要警惕
- PBO > 40%：策略大概率是过拟合的，不要用

### 3. Deflated Sharpe Ratio

**问题**：你试了 100 个策略，选了 Sharpe 最高的那个。这个 Sharpe 是虚高的——你只是运气好。

**Deflated Sharpe Ratio (DSR)**：
- 对原始 Sharpe 进行"折扣"——折扣幅度取决于你试了多少个策略
- 试的策略越多，折扣越大
- DSR 才是你真正应该相信的 Sharpe

**经验法则**：
- 试了 10 个策略：原始 Sharpe 打 8 折
- 试了 100 个策略：原始 Sharpe 打 5 折
- 试了 1000 个策略：原始 Sharpe 打 3 折甚至更低

### 额外防御措施

- **WFO (Walk-Forward Optimization)**：用滚动窗口训练，向前测试，更接近真实使用场景。
- **多重检验校正**：如果做了很多次实验，要对 p-value 进行 Bonferroni 校正。
- **样本外是唯一真理**：所有统计检验都是参考，真正的检验是未来的真实表现。

## Meta-Labeling 进阶

### 什么是 Meta-Labeling

```
第一层：基础模型 → 生成方向信号（买/卖/持有）
第二层：元模型 → 预测第一层信号的正确率
第三层：根据元模型的预测，决定仓位大小
```

### 为什么有效

- 基础模型负责"有没有机会"——方向对不对
- 元模型负责"这个机会靠不靠谱"——要不要重仓
- 这样你可以在保持整体方向性的同时，优化风险收益比

### 实战建议

1. **基础模型要简单**：元标签是优化工具，不是救命稻草。基础信号不行，元标签也救不了。
2. **元模型用简单模型**：逻辑回归、浅层 GBDT 就够了。
3. **元标签的目标**：不是预测涨跌，是预测"这个信号会不会赚钱"。
4. **仓位调整要平滑**：不要元模型说 80% 信心就满仓，说 50% 就空仓。要渐进式调整。

## ML 失效模式清单

### 出现以下信号，说明你的 ML 模型可能不行了：

1. **样本内 Sharpe 很高，样本外接近 0 或为负** → 过拟合
2. **特征重要性很奇怪**：最不重要的特征贡献最大，最重要的特征反而没用 → 数据泄露
3. **模型对微小扰动很敏感**：改一个数据点，预测结果完全变了 → 不稳定
4. **在牛市表现好，在熊市表现差** → 模型只是在学"市场涨不涨"，不是学你想让它学的东西
5. **交易成本扣掉后就不赚钱了** → 信号太弱，赚的钱不够付手续费
6. **持仓时间太短**：频繁交易，滑点和冲击成本吃掉所有利润
7. **和基准的相关性很高**：你以为你有 Alpha，其实你只是买了 Beta
8. **策略太拥挤**：很多人都在用同样的特征和模型，收益会快速衰减

### 诊断步骤

1. 检查数据有没有泄露
2. 检查标签是不是定义错了
3. 用更简单的模型做 baseline，看复杂模型是不是真的更好
4. 做 purged walk-forward，看稳定性
5. 扣掉真实交易成本，看还赚不赚钱
6. 检查和基准的相关性
