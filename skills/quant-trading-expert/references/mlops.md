## 为什么需要 MLOps

### 第一性原理

**量化策略和传统软件有什么不同？**

传统软件：
- 代码写好了，行为就固定了
- 测试通过了，上线就稳定了

量化策略：
- 即使代码一行不改，表现也会变
- 因为市场在变，数据在变，Alpha 在衰减

**所以量化系统需要：**
- 持续监控：这个策略现在还好吗？
- 自动告警：什么时候出问题了？
- 快速迭代：发现问题能快速回滚或切换

### 没有 MLOps 的后果

1. **不知道哪个策略在赚钱/亏钱**
2. **策略衰减了很久才发现**
3. **新版本上线出问题，不知道怎么回滚**
4. **实验做了一堆，没人记得哪个是哪个**

## 实验管理体系

### 什么是实验管理

**每一次策略试验，都要完整记录：**
- 什么参数？
- 用的什么数据？
- 结果怎么样？
- 谁做的？什么时候做的？

### 为什么重要

- **可复现**：三个月后你想复现这个实验，能复现出来
- **可对比**：不同实验之间能公平对比
- **不浪费**：避免重复做已经做过的实验

### 实验记录的核心字段

```python
@dataclass
class Experiment:
    experiment_id: str          # 实验唯一ID
    name: str                   # 实验名称
    strategy_id: str            # 用的哪个策略
    parameters: dict            # 完整参数
    dataset_version: str        # 数据版本
    created_at: datetime         # 创建时间
    created_by: str             # 谁做的
    status: str                 # running/completed/failed
    results: dict               # 结果指标（Sharpe、回撤等）
    notes: str                  # 备注/结论
```

### 最佳实践工具

- **MLflow**：开源实验追踪，最流行
- **Weights & Biases**：商业工具，UI 很好用
- **自研轻量版**：如果不想引入复杂依赖，用 SQLite + 简单 Web UI

## 模型注册中心

### 什么是模型注册中心

**所有策略版本的"档案馆"。**

每个策略版本都有：
- 版本号
- 完整参数快照
- 训练数据版本
- 性能指标
- 状态（草稿/回测/模拟盘/实盘/退役）
- 上线时间、下线时间

### 为什么需要

1. **可追溯**：出了问题，能追溯到是哪个版本、哪组参数
2. **可回滚**：新版本出问题，能快速切回旧版本
3. **可审计**：每笔交易都是哪个策略版本产生的？能查出来

### 注册中心的核心操作

- `register(strategy_version)`：注册新版本
- `get(strategy_id, version)`：获取特定版本
- `get_latest(strategy_id)`：获取最新版本
- `get_live()`：获取所有实盘运行的版本
- `compare(v1, v2)`：对比两个版本

## 漂移监控

### 什么是漂移

**模型上线后，表现慢慢变差——这就是漂移。**

漂移有两种：

#### 1. 数据漂移（Data Drift）
**输入数据的分布变了。**
- 以前波动率是 10%，现在变成 20%
- 以前趋势市多，现在震荡市多
- 模型没见过这种数据，表现就差了

#### 2. 概念漂移（Concept Drift）
**输入和输出的关系变了。**
- 以前突破后会延续，现在突破后马上反转
- 以前高 RSI 意味着超买要跌，现在不是了
- 逻辑变了，模型就过时了

### 怎么检测漂移

**数据漂移检测：**
- 监控特征分布（均值、方差、分位数）
- 分布变化超过阈值就告警
- 常用方法：KS检验、PSI（群体稳定性指数）

**概念漂移检测：**
- 监控模型预测的准确率
- 滚动 IC（信息系数）衰减
- 滚动 Sharpe 下降

### 漂移应对策略

1. **预警**：漂移刚出现就告警
2. **降级**：自动降低仓位
3. **回滚**：切回上一个稳定版本
4. **重训练**：用新数据重新训练
5. **退役**：实在不行就下线

## 策略生命周期管理

### 完整生命周期

```
发现 → 回测 → 模拟盘 → 实盘 → 衰减 → 退役
```

每个阶段都有明确的准入和退出条件：

| 阶段 | 准入条件 | 退出条件 |
|------|---------|---------|
| 发现 | 逻辑清晰，有第一性原理支撑 | 回测通过 |
| 回测 | 逻辑成立，样本外有效 | PBO < 0.3，Deflated Sharpe > 0 |
| 模拟盘 | 回测达标，小资金验证 | 3个月表现稳定 |
| 实盘 | 模拟盘通过，逐步加仓 | 漂移监控告警 |
| 衰减 | IC 连续下降，收益递减 | 自动减仓 |
| 退役 | 逻辑失效，或被更好的策略替代 | 永久下线 |

### 关键原则

1. **永远在开发新策略**：不要等旧策略失效了才找新的
2. **策略组合的生命周期要错开**：有的在上升期，有的在平稳期，有的在衰退期
3. **预设退役规则**：什么信号出现就说明这个策略不行了？提前定好
4. **不要恋战**：该退役就退役，沉没成本不是成本

## CI/CD 流水线

### 什么是 CI/CD

- **CI（持续集成）**：每次代码改动，自动跑测试
- **CD（持续部署）**：测试通过后，自动部署到环境

### 量化系统的 CI/CD

```
代码提交 → 自动测试 → 自动回测验证 → 人工审核 → 灰度发布 → 全量上线
```

### 各环节说明

**1. 自动测试**
- 单元测试：每个函数的正确性
- 回归测试：改了新代码，旧功能有没有坏
- 因果性测试：有没有引入前视偏差

**2. 自动回测验证**
- 新版本自动跑历史回测
- 和旧版本对比：性能是提升了还是下降了？
- 过拟合检测：PBO、Deflated Sharpe 自动算

**3. 人工审核**
- 机器出结果，人做决策
- 确认没有问题了，才允许上线

**4. 灰度发布**
- 先小流量跑（比如 10% 资金）
- 没问题再逐步扩大

## 可观测性与告警

### 核心监控指标

**策略性能指标：**
- 滚动 Sharpe（最近 30/90 天）
- 最大回撤
- 胜率、盈亏比
- IC（信息系数）

**风控指标：**
- 当日盈亏
- 累计回撤
- 杠杆率
- 敞口

**系统指标：**
- 数据连接状态
- API 延迟
- 错误率
- 资源使用（CPU、内存）

### 告警分级

**P0（立刻处理）：**
- 实盘策略连续亏损超过 X%
- 最大回撤超过阈值
- 系统宕机

**P1（当天处理）：**
- 滚动 Sharpe 连续下降
- 数据漂移告警
- 某个策略表现低于预期

**P2（观察即可）：**
- 性能略有波动
- 非核心指标异常

## 顶级机构怎么做

### Two Sigma
- 全自动化的 MLOps 流水线
- 从实验到上线，大部分流程自动化
- 人只做最终决策

### Renaissance
- 几千个策略并行运行
- 每个策略都有严格的监控和退役机制
- 策略数量比单个策略的表现更重要

### 共同原则
- **策略是消耗品，不是传家宝**
- **假设你的策略会失效，提前准备好一切**
- **可观测、可追溯、可回滚是底线**
