## 设计哲学

### 核心理念

**量化交易前端不是"好看的网页"，而是交易员的武器。**

设计目标：
1. **减少认知负荷** - 让交易员一眼看到最重要的信息
2. **加速决策速度** - 关键操作不超过2次点击
3. **控制风险暴露** - 危险操作结构上变难
4. **支持长时间使用** - 深色主题，低视觉疲劳

---

## 第一性原理推导

### 问题：交易员在看这个屏幕时，最关心什么？

```
第一层：我现在赚了还是亏了？（账户总览）
第二层：哪个仓位在影响我的盈亏？（持仓明细）
第三层：我现在该做什么？（下单面板）
第四层：我的系统还正常吗？（状态栏）
第五层：我的策略在正常运行吗？（策略监控）
```

### 推导结论

**三栏布局是最优解：**
- **左栏**：账户资产 + 持仓（回答"我现在怎么样"）
- **中栏**：图表 + 策略状态（回答"市场怎么样"和"我的策略怎么样"）
- **右栏**：下单面板 + 风险指标（回答"我现在该做什么"）

## 配色系统

### 为什么选深色主题？

**第一性原理推导：**
- 交易员每天面对屏幕8-12小时
- 浅色主题在暗环境下刺眼
- 深色主题减少视觉疲劳
- 专业交易终端全部使用深色

### 色板（对标Binance Pro）

```css
--bg-primary: #0b0e11;      /* 最深背景 */
--bg-secondary: #12161c;    /* 侧边栏背景 */
--bg-tertiary: #1e2329;     /* 卡片背景 */
--bg-hover: #2b3139;        /* 悬停状态 */

--text-primary: #eaecef;     /* 主要文字 */
--text-secondary: #848e9c;   /* 次要文字 */
--text-tertiary: #5e6673;    /* 提示文字 */

--up-color: #0ecb81;         /* 上涨绿 */
--down-color: #f6465d;       /* 下跌红 */

--brand-primary: #f0b90b;    /* 品牌黄（Binance黄） */
```

### 颜色使用规则

1. **绿色只用于上涨/盈利/安全**
2. **红色只用于下跌/亏损/危险**
3. **黄色只用于品牌强调/警告**
4. **灰色只用于次要信息**
5. **禁止滥用渐变和阴影**

## 核心组件设计

### 1. 账户选择器

**问题：** 之前的版本"我的账户"下拉框为空，无法选择OKX账户。

**解决方案：**
- 改为直接显示在左侧边栏，不需要下拉
- 每个账户显示交易所标识（OKX/Binance等）
- 连接状态用绿点实时显示
- 点击即可切换账户

### 2. 策略卡片

**设计原则：**
- 左边框颜色表示状态（绿=运行，灰=停止，红=警告）
- 单屏显示3-5个策略，不需要滚动
- 关键指标一眼看到（今日盈亏、累计收益）
- 操作按钮放底部，危险操作（停止）用红色

### 3. 风险面板

**设计原则：**
- 永远固定在右侧，不需要滚动
- 每个风险指标都有颜色等级（绿=安全，黄=警告，红=危险）
- 风险值用等宽字体，方便快速比较

## 交互设计原则

### 1. 减少点击次数

- 下单面板永远在屏幕右侧
- 切换账户只需要点击一次
- 策略启停不需要弹窗确认（直接执行+Toast提示）

### 2. 危险操作变难

- 平仓/停止策略需要二次确认
- 大额下单需要输入确认
- 风险参数修改需要密码

### 3. 即时反馈

- 所有按钮点击都有视觉反馈
- 数据更新实时刷新
- 错误信息明确具体

## 设计决策记录

### 决策1：为什么不用React/Vue？

**理由：**
- 当前项目是编译后的Docker镜像，没有前端源代码
- 先用纯HTML/CSS/JS做一个可运行的原型
- 验证设计后再考虑用框架重写
- 渐进式改进，不一次性推翻重来

### 决策2：为什么三栏布局？

**理由：**
- 这是专业交易终端的行业标准
- Jane Street/Citadel/Binance/OKX全部用三栏
- 经过几十年验证，这是最优布局
- 不要重新发明轮子

### 决策3：为什么用Binance黄作为品牌色？

**理由：**
- 用户熟悉加密货币交易界面
- Binance是行业标准，用户认知成本低
- 黄色在深色背景上最醒目
- 符合"交易终端"的用户预期
