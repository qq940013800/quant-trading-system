# AI/ML 模块分工架构设计

> 基于第一性原理和全球顶级机构最佳实践
> 清晰界定每个模块的职责边界、输入输出、运行时机和协同关系

## 一、核心原则：为什么要严格分工？

### 没有分工的系统会怎样？

```
策略一边跑一边调参数 → 过拟合
信号一边生成一边改逻辑 → 不可审计
前端一边展示一边算风控 → 延迟高、易出错
↓
系统越复杂越混乱，越改越亏
```

### 第一性原理

**不同时间尺度的任务必须物理隔离：**
- 离线任务（研究/优化）：可以慢，可以反复试，不影响实盘
- 在线任务（执行/匹配）：必须快，必须稳定，不能出错

**三条不可违反的边界：**
1. **离线优化，在线匹配** —— 策略参数研究时冻结，实盘只选不改
2. **宏观判断，微观执行** —— L1定大方向，L5找精确入场点
3. **后端算，前端看** —— 风险计算必须在后端，前端只负责展示和确认

## 二、策略优化 vs 策略匹配

### 一句话区分

| 模块 | 类比 | 目标 | 时间 |
|------|------|------|------|
| **策略优化** | 造车 | 让单个策略变得更好 | 离线、批量 |
| **策略匹配** | 选车 | 根据路况选最合适的车 | 在线、实时 |

### 策略优化模块（离线）

**输入：**
- 历史K线数据（10年+）
- 策略逻辑/规则模板
- 特征库（技术指标/量价/另类数据）
- 过拟合约束（PBO/CPCV/DSR）

**AI/ML 做什么：**
1. 特征工程：自动挖掘有效特征组合
2. 参数寻优：贝叶斯优化/进化算法找最优参数
3. 模型训练：XGBoost/LSTM预测信号方向
4. Meta-Labeling：二级模型决定信号做不做
5. 过拟合防御：CPCV验证 + PBO检测

**输出：**
- 优化后的策略参数（冻结！）
- 训练好的ML模型权重
- 过拟合验证报告（PBO/CPCV/DSR）
- 策略适用市场状态标签
- 注册到策略池，等待匹配

### 策略匹配模块（在线）

**输入：**
- 当前实时市场状态（波动率/趋势/流动性）
- 策略池（已优化好的策略列表）
- 各策略近期表现/健康度
- 当前组合风险敞口

**AI/ML 做什么：**
1. 市场状态识别：分类模型判断当前是趋势/震荡/危机
2. 策略推荐：协同过滤/强化学习选最合适的策略
3. 动态资金分配：根据综合得分分配仓位（Millennium模式）
4. 防抖动：策略切换要有冷却期，不能频繁换
5. 组合优化：考虑相关性，避免伪分散

**输出：**
- 当前应该运行哪些策略
- 每个策略分配多少资金
- 哪些策略应该暂停/退出
- 组合层面的风险预算分配
- 下发给执行层下单

### 数据流

```
数据湖（10年历史K线）
    ↓
策略优化（离线ML训练）
    ↓
策略池（冻结参数+模型）
    ↓
策略匹配（在线实时决策）
    ↓
执行层（下单交易）
    ↓
实盘表现 → 策略健康度监控 → 衰减/失效检测 → 回到策略优化模块
```

## 三、市场识别五层级

### 从宏观到微观的层级判断

```
        L5 K线形态识别（最微观）
       ┌─────────────────────┐
      │  锤子线/吞没/头肩顶    │
     ┌┴───────────────────────┐
    │ L4 价格行为分析           │
   │  实体/影线比 + 量价配合    │
  ┌┴────────────────────────────┐
 │ L3 市场趋势判断               │
│  方向（涨/跌）+ 强度（弱/中/强）│
┌┴────────────────────────────────┐
│ L2 市场结构分析                  │
│ 高低点序列 + 支撑阻力 + BOS/CHoCH │
┌┴──────────────────────────────────┐
│ L1 市场状态识别（Regime）           │
│ 趋势市/震荡市/危机市（最宏观）      │
└────────────────────────────────────┘
```

### 五层职责边界

| 层级 | 核心问题 | 时间尺度 | AI/ML 做什么 | 输出给谁用 |
|------|---------|---------|-------------|-----------|
| **L1 市场状态** | 现在是什么样的市场环境？ | 数周~数月 | 聚类算法（HMM/K-means）划分regime | 策略匹配模块（选策略） |
| **L2 市场结构** | 价格的高低点在哪里？趋势破了吗？ | 数天~数周 | 自动识别swing high/low，检测BOS/CHoCH | 趋势判断 + 入场时机 |
| **L3 市场趋势** | 往哪个方向走？走得强还是弱？ | 数小时~数天 | 趋势强度模型（ADX改进版） | 信号生成 + 仓位 sizing |
| **L4 价格行为** | 这根K线怎么走的？有没有量价配合？ | 数分钟~数小时 | 实体/影线特征提取，量价背离检测 | 入场确认 + 止损位计算 |
| **L5 K线形态** | 这是不是经典的反转/持续形态？ | 单根~3-5根K线 | CNN图像识别，24种经典形态分类 | 精确入场点 + 形态失效位 |

### 五层协同示例

1. **L1 市场状态：** "现在是震荡市" → 告诉策略匹配模块：别用趋势跟踪策略，用均值回归策略
2. **L2 市场结构：** "支撑位在19500，阻力位在20500，结构没破" → 告诉策略：在区间内高抛低吸
3. **L3 市场趋势：** "短期向上趋势，强度中等" → 告诉信号生成：只做多，不做空
4. **L4 价格行为：** "回踩支撑位，阳线实体大，成交量放大" → 告诉入场模块：这是个好的入场信号
5. **L5 K线形态：** "出现锤子线形态，置信度85%" → 告诉执行层：精确入场点 = 锤子线最低价上方

### 层级优先级

**层级越高，优先级越高。L1 > L2 > L3 > L4 > L5。**

- L1说是震荡市，L5出了个锤子线做多信号 → 不做
- 大环境不对，微观信号再好也不做

## 四、前后端分工架构

### 后端核心层 —— 决定你能不能赚钱

| 模块 | 职责 |
|------|------|
| **数据层** | K线数据采集与清洗、数据质量五维检查、前视偏差自动检测、集合分离 |
| **策略层** | 信号生成引擎、ML模型推理、过拟合三重验证、策略健康度监控 |
| **风控层** | 仓位 sizing、止损/止盈计算、组合风险预算分配、VaR/CVaR尾部风险 |
| **执行层** | 订单路由与执行算法、滑点成本模型、市场冲击预估、异步重试 |
| **绩效层** | 收益归因分析、策略生命周期管理、自动退役检测、决策审计日志 |
| **基础设施** | 实验管理、模型注册与版本管理、漂移监控、监控告警 |

### 前端交互层 —— 决定你会不会犯错

| 模块 | 职责 |
|------|------|
| **信息展示** | K线图与订单簿、收益曲线与回撤图、风险仪表盘、策略健康度状态 |
| **操作控制** | 下单/平仓面板、策略启停按钮、参数调整表单、危险操作二次确认 |
| **预警提示** | 风险预警弹窗、策略异常告警、过拟合风险提示、自动退役通知 |

## 六、常见错误与陷阱

### ❌ 错误1：在线优化策略

**错误做法：** 实盘的时候，模型一边跑一边根据最新数据调整参数。

**问题：** 这就是过拟合的根源！你在"看了答案再做题"。

**✅ 正确做法：** 离线优化，在线匹配。研究环境里用10年历史数据把策略优化好、冻结参数。实盘的时候，匹配模块只负责"选哪个策略跑"，不负责"改策略参数"。

### ❌ 错误2：用微观判断做宏观决策

**错误做法：** 看到一个锤子线（L5）就判断"趋势反转了"。

**问题：** 锤子线只是微观信号，需要L1-L4层层确认。

**✅ 正确做法：** 从宏观到微观，L1定大方向，L5找精确入场点。

### ❌ 错误3：止损靠人手动平仓

**错误做法：** 止损线画在前端，到了提醒人手动平仓。

**问题：** 人会犯"再等等"的错误。真到止损的时候，人总是想"再看一眼，说不定就反弹了"。

**✅ 正确做法：** 止损必须在后端强制执行，不能靠人。后端到了止损价自动平仓，人只负责事后复盘。
