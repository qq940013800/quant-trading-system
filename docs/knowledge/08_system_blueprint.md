## 0. BLUF（八条架构结论）

1. **系统已经过了"骨架期"**：`core/` 73 个模块、11,518 行、395 个测试全绿；缺的不是更多模块，而是
   **控制面（kill switch / 对账）、真实策略实现、以及验证算法的正确性**。
2. **最优先补的是"停得下来"**：kill switch 必须独立于策略进程；订单/持仓对账必须每轮运行。
   14 个失败案例里没有一个是"看错方向"，全部是"错了之后停不下来"（见 `06_failures_and_lessons.md`）。
3. **策略层是最大空洞**：`core/strategies/` 不存在，README 与 `registry.yaml` 引用的实现尚未落地；
   当前只有回测引擎内的 `DemoBreakoutStrategy`。**没有策略实现，风控与 ML 都是空转。**
4. **验证体系修正了 PBO**（已改 CSCV，14 个单测通过），但 `combinatorial_purged_cv` 名实不符，
   仍是单折 purge 的 K 折；在它修好前，**CPCV 结论不得用于上线决策**。
5. **AI/ML 的定位钉死为三件事**：L2 状态权重、L3 meta-labeling 过滤、概率→仓位映射；
   **ML 不生成方向**。这条来自 `04_ai_ml_systems.md`，也是 v1 设计哲学。
6. **成本与容量假设比模型精度更决定生死**：回测必须用保守成本（×1.5 压力）、平方根冲击、
   容量上限；没有 TCA 的实盘等于闭眼下注。
7. **明确不做**：HFT、做市、期权做市（需要 colocation/期权链/费率结构，零售 MT5 不可达）；
   第二标的与趋势周期上移列为**待人工确认**，不在本轮擅自扩围。
8. **企业级的判据不是"模块多"，而是**：任一组件崩溃时，系统能在已知时间内进入安全状态，
   且事后能完整还原"为什么"。

## 2. 从全球实践提炼的十条设计原则（来源见 01–07）

| # | 原则 | 来源 | 在系统中的含义 |
|---|---|---|---|
| P1 | 风险单位化 | Millennium pod、AHL 波动目标、R 倍数 | 所有仓位以"每笔风险占权益比例"为唯一单位，可加总、可限额、可熔断 |
| P2 | 研究与生产分离 | Two Sigma、Renaissance | 研究镜像与生产镜像分离；特征代码同一份；模型有版本卡与回滚 |

| P5 | 成本现实 | Citadel/Jane Street 执行 | 保守成本、平方根冲击、TCA、容量上限；成本×1.5 压力 |
| P6 | 生存优先 | 全部失败案例 | kill switch、对账、限额、熔断、回撤线、尾部对冲 |

## 3. 目标架构 v2

```
                 ┌────────────────────────── 控制面（独立进程） ──────────────────────────┐
                 │  Kill Switch  │  限额/熔断   │  配置中心   │  部署/回滚  │  告警        │
                 └───────┬──────────────┬─────────────┬──────────────┬──────────────────┘
                         │              │             │              │
┌─────────────┐   ┌──────▼──────┐  ┌────▼─────┐  ┌────▼──────┐  ┌────▼────────────┐
│ 数据面       │   │ 研究面       │  │ 决策面    │  │ 执行面     │  │ 可观测面          │
│ ingest      │→  │ features     │→ │ L1 位置   │→ │ 订单路由   │→ │ metrics/logs     │
│ validate    │   │ labels       │  │ L2 状态   │  │ 经纪商适配 │  │ traces/TCA       │
│ manifest    │   │ models       │  │ L3 触发   │  │ 状态机     │  │ drift/audit      │
│ 存储/血缘    │   │ CPCV/PBO/DSR │  │ meta/仓位 │  │ 对账       │  │ 看板/复盘         │
└─────────────┘   └──────────────┘  └───────────┘  └────────────┘  └──────────────────┘
                         │                │              │
                         └──── 策略注册表 / 模型注册表 / 实验账本（唯一事实源） ────┘
```

**新增/补强的四个面**：

1. **控制面**（新建 `core/control/`）：KillSwitch、LimitBook、ConfigProvider、DeployGuard。
   - kill switch 必须能由**独立进程/文件/IPC** 触发，不依赖策略进程存活；
   - 触发后：禁止新开仓、只允许减仓、记录触发原因与快照。
2. **执行面对账**（`core/execution/reconcile.py`）：每轮比对 `本地订单/持仓` vs `经纪商回报`，
   差异分级（金额/数量/方向/时间），超出容忍即告警并触发 kill switch。
3. **数据面 manifest**（`core/data/manifest.py`）：数据文件哈希、行数、时间范围、缺口、
   集合标签（CLEAN/KNOWN/SILENT），保证"训练用的数据"可复现。
4. **验证面**：CPCV 修正 + 守门员集成（PBO/DSR/CPCV 三指标进 `verification_middleware`）。

## 5. 策略路线（取长补短后的取舍）

**可立项（XAUUSD M5 单标的）**：

1. **趋势突破**：Donchian/结构突破 + ATR 止损 + 跟踪止盈；收益来源=行为+风险补偿；
   风险=点差与假突破；需要 regime 过滤（ADX/Hurst）。
2. **均值回归**：布林带/RSI 极值 + 区间识别；收益来源=行为过度反应；
   风险=趋势市逆势；必须带"区间状态"门控与时间止损。
3. **ML 过滤增强（meta-labeling）**：不独立产生方向，只对 1/2 的候选打分与定仓；
   收益来源=统计（弱信号）；风险=标签泄漏与概率未校准。

**明确不做**（写死为边界，待人工确认）：HFT、做市、期权做市、跨交易所套利。
理由：需要 colocation、L2/tick 全深度、期权链与费率结构，零售 MT5 不可达；做了也是负期望。

**暂缓**：横截面动量、因子投资、事件驱动、加密基差——需要多标的/多资产数据，先扩数据面。

## 6. AI/ML 落地规格（与 04 篇一致）

- **标签**：triple-barrier（止损/止盈/时间），标签窗口 = `max_holding_bars`；
  purge 宽度必须 ≥ 标签窗口（`core/models/cv.py` 已有断言）。
- **验证**：purged walk-forward（已有）+ CPCV（待修）+ PBO（已修）+ DSR（已修峰度口径）；
  禁止随机 KFold；`trials_N` 只增不减。
- **阈值**：`p` 必须做样本外校准（isotonic/Platt）；`k` 由训练集 `p` 的 q30/q70 分位映射；
  **删除固定 `meta_threshold=0.55` / `min_prob=0.45`**，改为 `q_lo/q_hi` 配置。
- **弃权**：`k=0` 是合法输出；只在分布内交易，分布外一律弃权。
- **衰减**：特征分布漂移优先于 PnL 报警；模型卡记录训练窗口、数据 manifest、指标、回滚点。
- **LLM 边界**：只做研究/运维文本处理，输出必须落到文件/测试/PR 并人审，**禁止进入下单路径**。

## 7. 上线门禁（Gate）

| 指标 | 通过线 | 说明 |
|---|---|---|
| PBO | < 0.5（警告 0.3） | 组合对称交叉验证，越低越好 |
| Deflated Sharpe | > 0（95% 置信更佳） | 已按 trials 修正 |
| CPCV 方向一致率 | ≥ 60% | 修好后启用 |
| 成本×1.5 后期望 | > 0 | 保守成本压力 |
| 样本外交易数 | ≥ 100 笔（或统计功效达标） | 大数定律 |
| 影子运行 | ≥ 4 周 | 实盘行情、模拟下单 |
| 回放校验 | 100% 一致 | Decision 五要素 |

## 8. 控制面与执行面规格（P0）

### 8.1 Kill Switch

```python
# core/control/kill_switch.py（拟）
class KillSwitch:
    def trigger(self, reason: str, source: str, ts_utc) -> None: ...
    def is_armed(self) -> bool: ...          # 只读状态，供决策面/执行面轮询
    def reset(self, operator: str, reason: str) -> None: ...   # 需人工+审计
```

- 存储：文件（原子写）+ 内存缓存；进程崩溃不影响状态；
- 触发源：对账差异、回撤线、数据过期、人工；
- 行为：新开仓拒绝、平仓放行、所有决策落审计；
- 测试：独立进程触发、策略进程死亡、重复触发幂等、reset 需授权。

### 8.2 对账

```python
# core/execution/reconcile.py（拟）
def reconcile(local_orders, local_positions, broker_orders, broker_positions,
              tolerances) -> ReconcileReport: ...
```

- 五类差异：缺失订单、多余订单、数量、方向、价格/时间；
- 容忍度来自配置；超限 → kill switch + 告警；
- 每轮交易后运行；日终全量对账。

## 9. 可观测性与治理

- **指标**：信号数/拒绝数、各层延迟、滑点、成本、回撤、相关性、漂移分数、对账差异；
- **日志**：结构化 + 决策快照 JSONL（已有）；
- **告警**：P0（kill switch/对账/数据过期）立即；P1（漂移/回撤）小时级；
- **治理**：变更需 PR + 测试 + 回放；配置变更审计；模型/策略版本可回滚。
