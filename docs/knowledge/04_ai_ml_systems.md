# 04｜AI/ML 系统：从标签到退役的完整生命周期

> L2 综合研究层。本文**不重讲** L1 `references/ml-playbook.md`、`overfitting-defense.md`、`mlops.md` 的教科书内容，
> 只写研究结论、判断与失败清单，并映射到 `core/` 与 `docs/trading/AI_ML_SYSTEM_DESIGN.md` 的冻结接口。
> 版本：v1.0 ｜ 建立：2026-11-02 ｜ 维护：研究层

## BLUF（先给结论）

1. **ML 的合法职能只有三类**：过滤（meta-labeling，回答"要不要下注"）、状态连续化（regime 离散标签 → 权重向量）、仓位映射（概率 → 系数）。把 ML 当"方向预言机"的设计，在 M5 黄金的信噪比下会退化成昂贵的随机数发生器。【推断】
2. **标签定义决定模型上限，模型选择只决定离上限多近。** 三重障碍的价值不在"更复杂"，而在它把路径与交易规格（止损宽度、最大持有期）写进了标签本身。【行业共识】
3. **验证体系是唯一能把真实 Alpha 与搜索噪声分开的装置。** 随机 KFold 在金融时序上不是"不够好"，而是方向性错误——它同时破坏时间顺序与样本独立性。【事实·可查证】（López de Prado, *AFML*）
4. **概率不是仓位。** `p=0.62` 没有交易含义：先做样本外校准，再用训练集经验分位映射成 k；分位阈值属于"阈值来自分布"，不属于绩效调参。【推断，同构于 AGENTS.md 不变量 3】
5. **弃权（k=0）是一等公民。** 只在 20% 时间开仓、其余输出"不确定"的模型，通常优于 100% 时间都在猜的模型。【行业共识】
6. **衰减的第一现场是特征分布，不是 PnL。** 等 PnL 报警，可观测性已经耗尽。【推断】
7. **LLM 是研究与运维的高价值文本/代码处理器，是交易决策路径上的不可审计风险源。** 分界线：输出必须落到文件/测试/PR 并人审，不得进入下单路径。【推断】
8. 本文最重要的交付物不是前 9 章，而是**第 11 章「系统性失败清单」**——上线前的逆向检查表。

## 1. ML 在系统中的位置：先定职能，再谈模型

决策链是 `L1 位置 → L2 状态 → L3 触发 → 仓位 → 风控 → 执行`（`AI_ML_SYSTEM_DESIGN.md` ①）。ML 可嵌入的位置远少于直觉允许的位置。

| 嵌入点 | 合法职能 | 输入 | 输出 | 失败形态 |
|---|---|---|---|---|
| L2 状态 | regime 权重连续化 | ATR 分位、ADX、Hurst、BOCPD | `w=(w_trend,w_mr,w_range)` | 状态很少却置信很高 |
| L3 触发后 | meta-labeling 过滤 | 候选信号 + 上下文特征 | `p`（盈利概率）、`k`（仓位系数） | p 未校准；k 与 p 非线性错配 |
| 仓位层 | 概率 → 风险预算 | p、k、波动率 | `lots` | 把 p 当 Kelly 直接放大 |
| 执行层 | 算法选择/节奏自适应 | 盘口、成交回执 | 拆单节奏 | 在线学习导致行为不可复现 |

**被排除的位置（重要）**：ML 不生成方向。方向来自有经济解释的规则骨架（突破/均值回归/区间）。
理由不是"ML 不行"，而是方向错了之后**归因成本**极高——你无法区分"市场变了"（该降仓）与"模型错了"（该回滚），而两者的正确应对完全相反。【推断】

## 2. 标签工程：上限在这里被锁死

### 2.1 四条硬要求
1. **可执行**：标签动作必须能被真实订单接口执行（最小手数、止损单类型、跳空成交）。
2. **含成本**：至少内扣平均往返成本，否则模型在学一个不存在的市场。【行业共识】
3. **含路径**：中途触及止损即出局，不能只看终点收益。
4. **与交易规格同构**：标注的止损宽度必须等于实盘 `entry_dist`（默认 2×atr0），持有期上限必须等于 `max_holding_bars`。不一致 = 训练一个你不交易的策略。

### 2.2 固定持有期 vs 三重障碍

| 维度 | 固定持有期 `y=sign(ret(t,t+h))` | 三重障碍（上/下/时间） |
|---|---|---|
| 路径信息 | 丢失（中途爆掉也只看终点） | 保留（先触哪个障碍） |
| 与实盘一致性 | 低（实盘有止损） | 高（止损即下障碍） |
| 样本重叠 | 严重（h 内相邻样本共享路径） | 同样严重，但**宽度可精确度量** |
| 类别不平衡 | 常为 50/50，看着"很好"，实则无信息 | 天然不平衡（多数为时间到期=0） |
| 用途 | baseline、对照实验、快速筛特征 | 主训练标签 |

**结论**：固定持有期标签的唯一正当用途是**对照**。若三重障碍训出的模型打不赢它，问题在障碍宽度或成本假设，而不在"模型不够强"。【推断】

### 2.3 三重障碍必须显式化的四个决策
多数实现把这四点留成隐式默认，这是标签层最大的隐性偏差来源。

1. **障碍宽度来源**：必须 ATR 倍数（`atr0` 入场冻结），不能固定点数，更不能"回测最优倍数"。
2. **同一 bar 双触**：必须选方向并写进代码。本系统取**保守假设——先触止损**（`core/models/labels.py`）。这是**冻结项**：改动它等于换标签，必须重跑全部验证。
3. **时间屏障到期**：标 0（本系统做法）会引入大量无信息样本并拉低正类率；标"到期浮盈方向"则污染标签。选前者，用**样本权重**处理 0 类，不要丢弃（丢弃=选择性偏差）。
4. **bar 分辨率**：M5 的 high/low 无法区分同一根 5 分钟内的先后。这是**不可修复的观测误差**，只能靠保守双触 + 更细粒度数据定价，不能靠模型学习补偿。

### 2.4 meta-labeling：为什么有效，何时无效
结构：**第一层给方向（规则）→ 第二层给"这次下注靠不靠谱"（ML）→ 第三层把靠谱程度映射成仓位。**

有效机制：方向层与下注层目标函数分离（覆盖率 vs 精确率不再互相拉扯）；标签从"三分类+时间到期噪声"变成明确的二分类，更适合 GBDT；不改变方向信号，出问题可**逐层回退**（关掉 meta 层即退回纯规则系统）。【推断】
失效条件：① 基础信号期望 ≤ 0 → meta 只学到"全部拒绝"，系统静默停摆；② 候选样本不足（M5 一年仅数百候选）→ 二级模型无法训练，此时**宁可不做 ML**；③ 方向层与 meta 层共用同一批特征 → 信息重复，`p` 虚高。

### 2.5 标签窗口 → embargo → 验证宽度是一条链
`max_holding_bars(L) → purge ≥ L（否则训练标签窗口伸进测试段）→ embargo ≥ L（否则序列相关把测试段信息带入训练段）`。
`core/models/cv.py` 已用 `PurgedCVError` 强制 `embargo_bars >= label_window_bars`——这是正确且少见的工程约束。任何改动 `max_holding_bars` 的提交必须同时重跑验证并复核该断言。

## 3. 特征工程与因果约束

**因果三定律**：只用 `available_at <= bar.close` 的数据（不变量 1）；只用**已收盘** bar（硬规则 5）；标准化/分位只能用训练段统计量。

| 泄漏源 | 表现 | 检查手段 |
|---|---|---|
| 全样本 z-score/分位 | 样本外 IC 突然崩塌 | 单测：时间索引倒序后特征不得变化 |
| 中心化滑窗（`center=True`） | 特征"提前"知道未来 | 代码扫描 + `as_of` 断言 |
| 用未来 bar 填缺口 | 缺口期特征异常平滑 | 缺口前后特征分布对比 |
| 当日收盘做当日决策 | 回测极好、实盘差一跳 | 引擎强制 `bar[i] 决策 → bar[i+1] 开盘成交` |
| 时区混用（服务器 vs UTC） | DST 切换日错位 1 小时 | `test_timezone_dst.py` |
| 生存者偏差 | 系统性偏乐观 | point-in-time 成分表 |
| 标签抖动 | 样本量与显著性虚高 | purge + 重叠样本计数 |

**质量判据**：有金融解释（能说出"谁在被迫交易"）；有效样本/特征数远大于 10，且"有效样本"按**独立事件数**（≈交易笔数）算，不按 bar 数算；分年度/分 regime 的 IC 同号率 > IC 均值；同族指标只留代表（10 个 RSI 是一个特征）；可解释，否则只能当【待验证假设】。

## 4. 验证体系

### 4.1 随机 KFold 必然错的两个独立原因
时间顺序被破坏（用"未来"训练"过去"）；样本不独立（重叠标签 + 序列相关使训练/测试共享信息）。任一成立即可否决。金融时序的正确形态**只有一种**：按时间分块 + purge + embargo。【行业共识】

### 4.2 purged walk-forward（生产标准）
训练窗扩张、测试块连续前滚、**不做随机打乱**；每折训练集末端剔除 `embargo_bars`（标签重叠），并剔除此前测试块之后 `embargo_bars`（序列相关）。产出不是"一个分数"而是**多折绩效分布**，发布判据基于分布左尾（最差折），不是均值。

### 4.3 CPCV：目的不是更准，而是拿到路径分布
N 个块取 k 个作测试，组合数 `C(N,k)`，得到多条互不相同的样本外路径——它回答的是"策略在多少种历史重排下依然成立"，这是单次 walk-forward 给不了的信息。注意：purge/embargo 必须在**每条路径**上执行，不能只在折边界；路径数不足时路径分布本身不可信，不要拿 3 条路径的方差谈显著性。

### 4.4 PBO：检验"选择行为"是否过拟合
PBO 衡量的不是策略好坏，而是**你挑策略的方式**是否可靠：训练段选出的最优者，在测试段落到后半区的频率。行业口径：`<0.2` 优秀、`0.2–0.3` 可接受但需监控、`≥0.5` 基本可判过拟合。
**实现纪律**：分割必须是**组合净化分割**，不能是随机置换——随机置换会打散时间结构，得到的 PBO 无解释力。PBO 是启发式统计量，不是证明，只是把"我试了很多次"变成可见数字。

### 4.5 Deflated Sharpe：给"试了多少次"定价
`SR_observed` 必须与"纯运气下 N 次试验的最大期望 SR"比较，折扣随 trials 增长。**trials 必须含失败与中止试验**（硬规则 11 的统计动机）。公式对偏度/峰度敏感，金融收益非正态，必须代入实际值而非假设正态。阈值口径各机构不同，**必须实验前冻结**。具体形式以 Bailey & López de Prado 原文与所用库官方文档为准。

### 4.6 发布判据（建议冻结）
`通过 = PBO<0.3 AND CPCV 路径分布左尾>0 AND 扣成本后 DSR 口径通过 AND 样本外/样本内衰减<预设阈值`。四者缺一不可。注意：这不是"能上线"，只是"有资格进模拟盘"。

## 5. 模型族：适用边界与失败模式

| 模型族 | 数据需求 | 可解释性 | 在 M5 黄金上的现实定位 | 主要失败模式 |
|---|---|---|---|---|
| 线性（Logistic/Ridge） | 低（数百样本起） | 高（系数符号可读） | **必须先打赢的 baseline**；meta 层首选之一 | 交互效应丢失；对异常值敏感 |
| GBDT（LGBM/XGB/CatBoost） | 中（千级样本起） | 中（重要性+SHAP） | 表格特征的事实标准；meta 层主候选 | 树多即过拟合；无时间外推能力；叶子值不可外推 |
| 序列模型（RNN/TCN/CNN） | 高 | 低 | 第二/三阶段候选，需极强验证 | 有效样本远少于参数；训练不稳；难审计 |
| Transformer | 很高 | 很低 | **当前不做**（设计文档⑤禁止引入） | 数据饥渴；注意力可视化≠可解释；易学"波动率而非方向" |
| RL（DRL） | 极高（需可交互环境） | 很低 | 方向预测**不做**；执行/做市是唯一合理切口 | 奖励设计即策略；非平稳使 replay buffer 失效；回测-实盘 gap 无法量化 |

- **GBDT 超参纪律**：结构约束写死（深度 3–6、early stopping、subsample），取值走配置，**禁止按 Sharpe 网格搜**。`core/models/gbm.py` 已把 `max_depth ∈ [3,6]` 写成构造期断言。
- **线性模型不可跳过**：GBDT 打不赢线性基线，通常不是调参问题，而是**特征里没有非线性信息**；此时加复杂度只是在买过拟合。【推断】
- **RL 的唯一切口**是执行算法（拆单节奏、被动/主动切换）：那里有可反复采样的模拟器与明确即时成本函数。方向预测两样都没有。

## 6. 概率 → 仓位映射：从 p 到 lots 的四步

```
① 校准：OOS 上做 isotonic/Platt，把原始分数变成频率意义正确的概率
② 映射：k = clip((p - q_lo)/(q_hi - q_lo), 0, 1)      # 分位来自训练集经验分布
③ 预算：risk_amount = equity × risk_pct × k × regime_weight
④ 上限：lots = clip(risk_amount/(entry_dist × point_value), 0, kelly_cap × base_lots)
```

1. **校准先于映射**：未校准的 p 做分位映射等于"用排名当概率"，漂移时系统性高估。
2. **阈值来自分布**：固定 0.5/0.55 当开仓阈值是把连续信号人为二值化，且来源无法审计。
3. **k 要平滑**：仓位跳变本身就是成本。
4. **Kelly 只作上限**：fractional Kelly（如 0.25×）是上限约束而非目标仓位；当目标会在高估时爆掉。

**弃权应显式为第三类输出**，而不是"p 接近 0.5 时不动"的隐式行为：

| 触发条件 | 输出 | 理由 |
|---|---|---|
| `p < q_30` | `k=0`，`reject_reason="meta_p_below_q30"` | 低于训练分布底部三成 = 没见过 |
| 特征超出训练分布支持（PSI 超阈） | `k=0` 或 `k×0.5` + 告警 | OOD 输入，模型无资格表态 |
| 模型版本未注册/校验和不匹配 | 硬拒（fail-safe） | 不可审计的模型不得下单 |
| 熔断/新闻窗口 | 硬拒（风控层给出） | ML 无权覆盖风控 |

**弃权率本身是监控指标**：从 30% 涨到 80% 往往先于 PnL 恶化，是最便宜的早期信号。【推断】

## 7. 在线漂移与衰减

| 类型 | 定义 | 监控量 | 响应 |
|---|---|---|---|
| 数据漂移 | 输入分布变了 | PSI/KS（特征层，按训练分布分桶） | 观察 → 降 k |
| 概念漂移 | 输入→输出关系变了 | 滚动命中率、滚动 IC、滚动校准误差 | 降 k → 回滚 |
| 竞争衰减 | 信号被套利掉 | 拥挤度、成交质量、成本占比 | 退役 |

**顺序很重要**：数据漂移先出现，概念漂移后出现；等 PnL 恶化才动作，等于放弃前两级预警。

**动作阶梯（必须预先冻结，不能临场决定）**
```
PSI∈[0.1,0.25) 或 命中率跌破训练段 1σ      → P3 观察并记录
PSI≥0.25 或 命中率跌破 2σ                  → P2 降 k×0.5 + 人工复核
连续 N 日滚动 Sharpe<0 且校准误差超阈        → P1 停开新仓，只平仓
版本不匹配/不可审计/风控冲突                → P0 立即停策略
```
`0.1/0.25/N` 是行业常用起点【行业共识】，**本系统必须外置到 config 并标注来源**，不得散落在代码默认值里。

**重训练纪律**：定时重训（如季度）可接受；**由漂移触发的重训**等于"看到结果再改模型"，是一次隐性试验，**必须计入 trials**。重训前后须在同一段 OOS 上对比；重训不得改标签定义与决策规则版本——改了就是换策略，需重走完整验证。

## 8. 模型注册与回滚

**版本三元组**：`model_version` 必须唯一定位到 **代码 commit + 数据版本 + 配置快照**。只写 `gbm-v3` 的版本号三个月后无法复现，等于没有版本。【推断】

注册中心最小操作：`register()`（不可变写入，含 trials）、`set_state()`（draft→backtest→shadow→live→retired，单向）、`get_live()`（审计用）、`rollback()`（回滚本身也要留审计记录）。

**回滚的三个坑**：① **在途持仓归属**——必须显式规定，建议"持仓沿用开仓时的模型版本与冻结参数（`atr0`/`entry_dist`/`stop`），新仓用新版本"，否则出现"新逻辑管旧仓位"的不可解释状态；② **状态机跳变**——`live→draft` 应被拒绝，正确路径是 `live→retired` 再新建；③ **回滚≠恢复**——恢复的是模型不是市场，回滚后应重新走 shadow 观察期，除非同时处于降仓状态。

## 9. 可解释性与审计

| 层次 | 问题 | 方法 | 落点 |
|---|---|---|---|
| 全局 | 模型在依赖什么 | **OOS** permutation importance、SHAP 汇总 | `core/models/baseline.py::permutation_importance` |
| 局部 | 这一笔为什么开/不开 | 单样本归因 + 各层输入快照 | `Decision.feature_snapshot`、`core/explainability/decision_explainer.py` |
| 反事实 | 换阈值会怎样 | 同一快照重放不同 q_lo/q_hi | `core/audit/replay.py` + 决策规则版本对照 |

**审计最小集**：特征快照、`model_version`、`threshold_dataset`（CLEAN/KNOWN）、`decision_rule_version`、`reject_reason`、最终手数。`Decision` schema 已覆盖，是本系统相对多数个人系统的真实优势，应保持。
**判断**：可解释性不是给监管的装饰，是**故障隔离工具**——没有局部归因，你无法回答"数据坏了还是模型坏了"，而这决定了该修数据还是该回滚。

## 10. LLM：可用 / 不可用

| 场景 | 判定 | 约束 |
|---|---|---|
| 读代码/文档、摘要、测试骨架 | ✅ 可用 | 产物落仓库并人审，可 diff |
| 日志聚类、事故复盘初稿 | ✅ 可用 | 人在环，结论需人工确认 |
| 生成/校验 schema、配置、SQL | ✅ 可用 | 必须有单测或 dry-run 兜底 |
| 知识库检索问答、文档一致性检查 | ✅ 可用 | 只读，不改状态 |
| 把 LLM 输出当下单信号 | ❌ 禁止 | 不可复现、不可审计、风险不可定价 |
| 用 LLM 打分当标签/特征 | ❌ 默认禁止 | 除非完全离线 + 冻结模型/prompt + 可复现 |
| 用 LLM 搜策略参数 | ❌ 禁止 | 等于无限 trials 且无法诚实计数 |
| 让 LLM 判断因果（"为何突破失败"） | ❌ 禁止 | 生成叙事而非因果，会污染复盘 |
| 实时热路径 | ❌ 不适用 | 延迟、成本、非确定性均不可接受 |

**安全约束**：外部文本（新闻、网页、`web_fetch` 结果）进入上下文时按**数据**处理，绝不当指令——prompt 注入的直接后果可能是"生成一个看起来合理的下单脚本"；LLM 产出禁止生成无计算过程的数字型结论；LLM 不得直接写 `configs/`、`registry.yaml`、`mt5/`（同 AGENTS.md 停止条件）。

## 11. 「哪些 ML 做法在金融时序上系统性失败」

> 格式：**做法 → 现象 → 根因 → 替代**。判据是"系统性"——不是有时不行，而是结构上必然退化。

1. **随机 KFold / `shuffle=True`** → 样本外崩塌 → 破坏时序 + 样本不独立 → purged WF + embargo。
2. **全样本标准化/分位化** → 回测虚高、实盘失效 → 用未来信息定标尺 → 只用训练段统计量、逐折重算。
3. **只报最优结果不报 trials** → DSR 虚高 → 选择偏差 → trials 原子递增含失败试验。
4. **反复看 OOS 调参** → OOS 退化成训练集 → 信息泄漏进决策 → 一次性留出集 + 决策规则冻结。
5. **固定持有期收益当主标签** → 学到"波动率方向" → 路径信息丢失 → 三重障碍 + 成本内扣。
6. **预测价格水平** → R² 很高但无交易价值 → 非平稳序列的伪拟合 → 预测事件/相对量，不预测价格。
7. **`center=True` 或未来填充** → 回测奇迹 → 前视偏差 → `as_of` 断言 + 倒序索引单测。
8. **不扣成本的标签与回测** → 净收益为负 → 信号弱于摩擦 → 标签与回测都内扣真实成本。
9. **不平衡样本不处理**（正类 2%） → 退化为"永远不交易" → 类别不平衡 → 样本权重 + 用 PR 而非 ROC。
10. **用 accuracy 当主指标** → 99% 准确率的空模型 → 指标与目标不一致 → 期望值 / PR-AUC / 校准误差。
11. **p 直接乘 Kelly** → 少数几笔爆掉 → 概率未校准 + Kelly 对高估极敏感 → 校准 + 分位映射 + fractional 上限。
12. **小样本上深度学习做方向** → 训练集完美、OOS 随机 → 参数量 ≫ 有效样本 → 线性/GBDT 起步。
13. **Transformer 直接套价格序列** → 学到的多是波动率与时间戳 → 数据饥渴 + 无平移不变性 → 先做特征工程。
14. **RL 端到端学交易** → 奖励设计即策略、无法归因 → 非平稳 + 稀疏奖励 → 只用于执行/做市。
15. **按 Sharpe 网格搜超参** → 挑中噪声 → 多重检验 + 非线性目标 → 结构约束 + 分布阈值 + DSR 折扣。
16. **样本外好就上线** → 上线后线性衰减 → 竞争衰减 + 状态切换 → shadow 期 + 分档上线 + 预设退役线。
17. **只用 PnL 做监控** → 发现太晚 → 反馈滞后 → 特征层 PSI + 模型层命中率 + 组合层 Sharpe 三级监控。
18. **漂移触发无限重训** → 隐性无限 trials → 每次重训都是一次选择 → 重训计入 trials。
19. **标的池只取"当前还活着"的品种** → 系统性偏乐观 → 生存者偏差 → point-in-time 成分表。
20. **忽略拥挤** → 收益快速衰减、成交变差 → 同质化策略挤同一流动性 → 容量评估 + 拥挤度监控。
21. **用集成/stacking 提分** → 复杂度暴涨、解释性归零 → 金融数据相关性极高、集成收益递减 → 先修标签与验证。
22. **用训练集特征重要性做解释** → 结论反向 → 反映拟合而非预测 → OOS permutation importance。
23. **把因子 IC 显著性当成交易显著性** → 交易层不成立 → 忽略成本与容量 → 全链条净绩效验证。
24. **用 LLM 生成标签/因子并直接采用** → 不可复现、无法审计 → 非确定性 + 无版本 → 仅离线、冻结版本、人审入库。
