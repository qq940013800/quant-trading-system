# 全球顶尖量化实践知识库（Knowledge Base）

> 目的：把「全球实盘顶尖机构 / 交易员 / 交易冠军 / 量化策略 / AI-ML / 语言与代码库」的**可复制成功经验**，
> 沉淀成可被工程直接消费的知识层，并逐条映射到本仓库 `core/` 的实现与缺口上。
>
> 本层不追求"资料汇编"，只回答三个问题：
> 1. **他们到底做对了什么**（机制，而不是故事）；
> 2. **哪些可以复制、哪些不能**（区分机制与运气）；
> 3. **我们要改哪个模块、按什么优先级改**（落到文件与测试）。

## 1. 证据等级（全文强制标注）

| 标记 | 含义 | 写作要求 |
|---|---|---|
| 【事实·可查证】 | 公开可核验的事实（监管文件、论文、公开采访、公司披露） | 必须能给出处；数字不确定就不写数字 |
| 【行业共识】 | 量化行业普遍接受、但无单一权威出处的做法 | 写"共识"，不写成"某机构内部规定" |
| 【推断】 | 由事实+逻辑推导出的判断 | 必须写出推理链 |
| 【待验证假设】 | 本系统尚未验证的推断 | 必须写"需要什么证据才能升级" |

**硬约束**：
- 不编造收益率、AUM、员工数、内部流程细节。机构内部做法只有公开来源才可写成【事实】。
- 基金业绩只引用公开披露口径，并注明"费前/费后、时间区间"。
- 人物轶事只保留能提炼出**可执行规则**的部分，其余不进知识库。

## 4. 知识 → 系统的落地闭环（本仓库的硬规则）

```
研究（L2 文档）
  → 判断：机制是否可复制？边界条件是什么？
  → 设计：落到哪个模块？接口是什么？（docs/trading/AI_ML_SYSTEM_DESIGN.md 冻结接口）
  → 实现：core/ 下的代码
  → 验证：tests/ 单测 + 样本外实验（registry.yaml 登记 trials_N）
  → 复盘：docs/SUCCESS_PLAYBOOK.md（验证过的胜法）/ docs/ERROR_LOG.md（事故）
```

**三条不可协商的不变量**（见根目录 `AGENTS.md`）：
1. 因果单向：只用 `available_at <= bar.close` 的数据；
2. 决策可审计：每笔接受/拒绝可还原；
3. 阈值来自分布：不用绩效网格搜索产生阈值。

知识库的任何结论，若与这三条冲突，以三条为准。

## 6. 维护纪律

1. **一篇一主题**，超过 400 行拆篇；
2. 新增结论必须带证据等级；【事实】必须能落到 `09_sources.md`；
3. 每季度复审一次「是否被证伪」——尤其是依赖市场结构的结论（拥挤、容量、监管）；
4. 与系统实现不一致的结论，要么改文档、要么改代码，不允许长期并存；
5. 本目录**只增不改历史结论**：被证伪的结论保留并标注 `【已证伪·日期·证据】`，供复盘。
