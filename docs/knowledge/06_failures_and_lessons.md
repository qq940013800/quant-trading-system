# 06 失败案例与教训（Failure Anatomy）

> 版本：v1.0 ｜ 建立：2026-11-02 ｜ L2 综合研究层 ｜ 规范：`docs/knowledge/README.md`
> 关联：`docs/ANTI_FRAGILE.md`（20 条必死清单）、`docs/ERROR_LOG.md`（本仓库事故）、`02_traders_and_champions.md`

## BLUF

1. **死法高度集中**：14 个案例中，杠杆/流动性占 9 个、模型外推与相关性突变占 7 个、
   运维与发布占 3 个、治理与欺诈占 5 个（可重叠）。**没有一个是"预测错了方向"致死的。**
   【推断（基于本篇案例统计）】
2. **致命机制是同一个**：**杠杆 + 相关性在压力下趋近 1 + 融资方同时抽贷/提保证金 = 强制平仓螺旋**。
   LTCM、Archegos、Amaranth、2007 量化地震、2024 日元套息是同一台机器的不同外观。【推断】
3. **早期信号几乎总是先出现**：保证金上调、repo haircut 上升、单一标的集中度、相关性同步上升、
   订单速率异常、对账差额。**不是没有预警，而是预警没有接线到可以自动动作的开关。**【行业共识】
4. **风控的失效点通常在"组织"而非"模型"**：前中后台同一人（Barings）、跨机构看不到总敞口
   （Archegos）、客户资金可被挪用（MF Global/FTX）、部署缺少原子性（Knight）。
   技术控制必须能约束**有权改参数的人**。【行业共识】
5. **对本系统的直接含义**：这些死法在本仓库都能落成断言与测试（§3 矩阵），
   但**大多数当前只是文档声明，不是可执行代码**——这是最大的剩余风险。【待验证假设】

## 0. 读法与根因分类法

每个案例只写五段：**触发链 → 根因分类 → 可观测早期信号 → 工程控制 → 本系统断言**。
不写故事、不写人物评价；数字一律"据报道"，不做跨案例的金额比较（名义敞口口径不可比）。

| 代码 | 根因 | 判定问句 |
|---|---|---|
| L | **杠杆** | 若敞口减半，这次还会致命吗？ |
| Q | **流动性** | 平仓需要多少天 ADV？谁在对面？ |
| M | **模型外推** | 这条关系在过去 N 年是否只是"这段样本成立"？ |
| C | **相关性突变** | 压力下所有头寸是否变成同一个头寸？ |
| O | **运维/发布** | 这次事故能否由一次错误部署单独解释？ |
| G | **治理** | 有没有一个人同时拥有"下单、记账、改限额"三种权力？ |
| F | **欺诈** | 账面资产与可验证资产是否分离？ |

## 1. 十四个案例

### 1. LTCM（1998）【L·Q·M·C】
- **触发链**：1998-08-17 俄罗斯违约 → 全球 flight-to-quality → 利差全面走阔 → 收敛类头寸同时亏损 → 保证金追缴 → 被迫在流动性最差时平仓 → 亏损自我强化。据报道 9 月由纽约联储协调 14 家机构注资约 36 亿美元。
- **根因**：杠杆（据报道资产/权益约 25:1 量级，名义敞口更高）；模型外推（假设历史利差关系平稳、假设总能融资）；**假分散**——所有"独立"策略本质是同一笔"做空流动性/做空波动率"。
- **早期信号**：swap spread 异常走阔；off-the-run/on-the-run 价差扩大；repo haircut 上升；多个"不相关"策略同向回撤；保证金调用频率上升。
- **工程控制**：按"相关性=1"做压力测试；融资流动性监控（haircut、rollover 失败）；杠杆上限按压力情景而非历史波动；**预定义减仓阶梯**（到 X% 回撤自动减 Y%，不留给现场判断）。
- **本系统**：新测 `tests/test_risk/test_portfolio_risk.py` 增加"危机相关矩阵"情景，断言组合回撤 ≤ 预算；`core/risk/portfolio_risk.py` 输出"有效独立头寸数"，低于阈值告警。

### 2. 2007 八月量化地震（2007-08-06~09）【C·Q·L】
- **触发链**：次级抵押担忧 → 某大型多策略基金去杠杆 → 统计套利多因子基金持仓高度相似 → 同时平仓 → 因子收益剧烈反转 → 更多基金触发风控减仓。据报道多家知名量化基金数日内回撤达 5%–10% 量级，个别更严重。
- **根因**：**拥挤**（同一批因子、同一批标的）；杠杆；流动性错配（持仓的退出天数 > 负债的容忍期）。
- **早期信号**：market-neutral 基金净值同步性异常上升；短期反转因子收益突然变大；同一因子在不同管理人处同时亏损；prime broker 收紧融资。
- **工程控制**：因子拥挤度指标（同类策略持仓重叠、空头余额占流通比）；单因子暴露上限；**流动性分层**（按 ADV 计算退出天数，分层设限）；禁止在流动性最差时段强制平仓。
- **本系统**：`core/monitoring/drift_monitor.py` 增加"因子暴露漂移 + 拥挤度"输出；断言：任一因子组合暴露 ≤ 上限，超限拒绝新开仓。

### 3. Knight Capital（2012-08-01）【O·G】
- **触发链**：新代码部署到 8 台服务器中的 7 台 → 第 8 台残留旧版本，其中一个被"重新利用"的功能开关在旧代码里仍指向老逻辑 → 开盘后旧路径被激活，子订单累计字段未重置 → 重复无限发单 → 约 45 分钟。据报道税前损失约 4.4 亿美元，公司随后被收购；SEC 后以违反市场准入规则（15c3-5）罚款。
- **根因**：**发布不原子**（部分成功即视为成功）；缺少 pre-trade 风险检查（累计数量、名义额、速率）；**没有一键 kill switch**；告警产生但处置链断裂。
- **早期信号**：订单速率与拒单率同时飙升；成交回报与本地订单状态不一致；持仓/名义额突破限额告警；同一标的被反复小额成交。
- **工程控制**：部署原子性 + 全节点版本哈希校验；canary + 部署冻结窗口；pre-trade 限额（单笔/累计/速率/名义额）；kill switch（目标 <1 秒生效）；告警必须绑定 on-call 与自动降级动作。
- **本系统**：`core/execution/engine.py` 增加"订单速率 + 累计名义额"硬上限断言；新增 kill switch 单测（触发后拒绝一切下单）；部署脚本校验 `mt5/` 与 Python 端版本一致（未验证）。

### 4. 2010 Flash Crash（2010-05-06）【Q·O·M】
- **触发链**：某大型基本面卖方用**不考虑价格与时间**的算法在 E-mini 卖出大额合约（SEC/CFTC 联合报告口径约 7.5 万张）→ 高频做市商互相成交（"hot potato"）→ 盘口深度蒸发 → 市价单穿越至 stub quote → 期货/ETF/个股跨市场不同步 → 道指盘中跌约 9% 后回收。
- **根因**：流动性瞬间消失；**市价单 + 无价格约束**；跨市场机制不一致（当时尚无 LULD/个股熔断）。
- **早期信号**：盘口深度骤降；高频参与率异常升高；ETF 与期货价格偏离；消息速率（message rate）飙升。
- **工程控制**：只用限价单；价格带（collar）与最大滑点；盘口深度监控；薄流动性时段（开盘/收盘/事件）禁新开仓。
- **本系统**：`core/backtest/costs.py` 增加"流动性冲击"情景（深度按分位数塌缩）；断言：回测中禁止无限价保护的市价穿越；实时侧监控 spread/depth 并降级。

### 5. Volmageddon / XIV 终止（2018-02-05）【M·C·G(产品结构)】
- **触发链**：低波动 regime 长期持续 → 做空波动率产品规模累积 → VIX 单日由约 17 冲至 50 附近 → 反向 VIX 短期期货 ETN 的盘后指示价值崩塌 → 发行方行使提前终止权（据报道）。同日其他杠杆反向产品暴跌后下调杠杆。
- **根因**：**产品结构**（每日再平衡的做空波动率，天然负凸性）；模型外推（把"低波动"当稳态）；反射性（再平衡与赎回放大波动）。
- **早期信号**：VIX 期货期限结构由 steep contango 转平/倒挂；ETN 相对 NAV 溢价；空波动率产品 AUM 集中度上升；波动率风险溢价被压缩到历史低位。
- **工程控制**：禁止裸卖波动率；任何 short-vol 暴露必须配尾部对冲；压力测试 = 波动率指数单日 +100%；产品条款（终止权/再平衡规则）必须被建模。
- **本系统**：`core/backtest/stress_test.py` 增加 vol shock 情景；断言：策略在 VIX +100% 情景下损失 ≤ 风险预算，否则拒绝上线。

### 6. Archegos（2021-03）【L·G·C·Q】
- **触发链**：家族办公室通过多家 prime broker 的总收益互换建立高度集中的股票多头 → 某核心标的大额增发导致股价下跌 → 各 PB 同时追缴保证金 → 强制平仓（各家看不到彼此敞口）→ 多家 PB 巨额损失（据报道 CS 约 55 亿美元、Nomura 约 29 亿美元量级）。
- **根因**：杠杆；**透明度/治理**（跨机构总敞口无人可见）；单一发行人集中；互换保证金按单腿而非组合计量。
- **早期信号**：单一发行人集中度；跨多家机构融资；swap 名义额异常；借券费率上升；持仓篮子相对大盘持续偏离。
- **工程控制**：跨全部交易对手汇总敞口；单一标的/发行人限额；按压力情景（如 -30%）估值；保证金按组合计量并要求对手方披露。
- **本系统**：`core/risk/portfolio_risk.py` 增加"单一标的/发行人集中度"断言；新测：构造 90% 单票敞口必须被拒绝。

### 7. MF Global（2011-10-31）【G·L·Q】
- **触发链**：大额自营 repo-to-maturity 欧洲主权债头寸（据报道约 63 亿美元）→ 评级下调与保证金追缴 → 流动性紧张 → 客户隔离资金被用于补缺口（据受托人报告）→ 10-31 破产；据报道客户资金缺口约 16 亿美元。
- **根因**：**治理**（自营冒险发生在受监管经纪商体内，风险委员会形同虚设）；杠杆；客户资金隔离机制失效。
- **早期信号**：CDS 走阔/评级下调；repo haircut 上升；保证金追缴频率上升；客户提款异常；三方对账出现差额。
- **工程控制**：每日三方对账（银行/经纪/内部账本）；客户资金与自有资金物理隔离；自营头寸独立限额；合规报告线独立于业务线。
- **本系统**：`core/audit/replay.py` 每日对账；断言：本地账本与券商报表差异必须为 0 才允许继续下单，非 0 进入只平仓模式。

### 8. Barings（1995-02）【F·G·L】
- **触发链**：交易员用错误账户 88888 长期隐藏亏损 → 大量卖出日经跨式 → 1995-01-17 神户地震 → 日经持续下跌 → 交易所保证金催缴由总部不断注资填补 → 亏损无法再隐藏 → 累计亏损据报道约 8.27 亿英镑，银行以 1 英镑售予 ING。
- **根因**：**欺诈**；治理（同一人同时管前台交易与后台结算）；杠杆；尾部事件。
- **早期信号**：交易所保证金调拨异常增大；某个账户不出现在总部合并报表；对账长期挂账无法解释；关键岗位长期不休假。
- **工程控制**：前中后台职责与系统权限分离；强制休假与轮岗；交易所持仓与内部账本**实时**对账；限额由独立风控监控而非交易台自报。
- **本系统**：制度层（不可代码化部分）+ 断言：执行凭证与风控凭证不得为同一套；新增权限矩阵测试（下单进程不能改写风控配置）。

### 9. Amaranth（2006-09）【L·Q·G】
- **触发链**：天然气日历价差头寸高度集中 → 2006 年 8–9 月价差不利变动 + 交易所上调保证金 → 无法满足追缴 → 清盘并出售能源组合（据报道亏损约 66 亿美元，能源账面售予两家机构）。
- **根因**：杠杆；**容量/流动性**（价差市场的深度远小于名义规模）；风险限额被覆盖或形同虚设；治理。
- **早期信号**：单一口径风险占比过高；交易所提高保证金；价差波动率飙升；持仓/未平仓量比例过高。
- **工程控制**：按"占未平仓量比例"设限而非按名义额；价差策略的流动性折扣；单一交易员/单一策略集中度上限；保证金上调情景测试。
- **本系统**：断言：任何持仓 ≤ 该合约未平仓量/ADV 的 X%；`portfolio_risk` 对集中度超限必须拒绝而不是告警。

### 10. 2020 负油价（2020-04-20）【M·O·G(产品)】
- **触发链**：库容接近饱和 → 近月合约临近交割 → 交易所公告其系统支持负价格 → WTI 5 月合约到期结算价为负（据报道约 -37.63 美元/桶）→ 持有到期合约的零售/银行产品出现穿仓（据报道某银行产品亏损达数十亿元人民币量级）→ 部分经纪商系统无法表示负价。
- **根因**：**模型外推**（隐含假设"价格下界=0"）；产品/机制（ETF 展期、交割义务、无储运能力）；运维（价格字段无符号、负价未处理）。
- **早期信号**：库容利用率创新高；近月-次月价差极端 contango；交易所公告与保证金上调；ETF 展期公告。
- **工程控制**：价格可为负的显式建模（禁止 `abs()`/`max(0, price)`）；交割月前强制移仓；产品条款审计；极端 contango 情景测试。
- **本系统**：断言：任何价格处理不得假设 `p > 0`；回测支持负价 bar；新测：喂入负价不得崩溃且止损/保证金逻辑正确。

### 11. Renaissance RIEF（2020-03）【M·C·L】
- **触发链**：2020 年 3 月流动性危机 → 多头组合与对冲篮子同时失效（危机中相关性结构改变）→ 杠杆放大回撤。据报道该机构股票基金全年亏损约 20% 量级，同年其旗舰基金为正收益。
- **根因**：**模型外推**（对冲比率按常态样本估计）；相关性突变（危机中"对冲"变"同向"）；杠杆。
- **早期信号**：滚动对冲效率下降；因子暴露漂移；赎回压力；保证金占用上升。
- **工程控制**：危机相关性假设（对冲失效情景）；对冲有效性实时监控；杠杆按压力情景设限；负债端流动性与资产端匹配。
- **本系统**：`core/monitoring/drift_monitor.py` 增加"对冲效率"指标；断言：策略在"对冲完全失效"情景下损失 ≤ 预算。

### 12. Melvin Capital / GME（2021-01）【C·L·M】
- **触发链**：GME 被高度做空（据报道空头占流通股比例极端）→ 散户在社交平台组织买入 + 看涨期权 gamma 挤压 → 股价暴涨 → 空头回补 + 追保 → 据报道该基金 1 月亏损约 53%，获约 27.5 亿美元注资，2022 年清盘。
- **根因**：**拥挤交易**；空头的理论损失无上限；杠杆；风险模型未纳入借券成本/召回风险/挤仓情景。
- **早期信号**：空头占流通股比例；借券费率飙升；期权 gamma 与未平仓量；散户订单流；days-to-cover。
- **工程控制**：空头敞口按流通股/ADV 设硬上限；把借券成本与召回风险计入模型；挤仓情景压力测试；禁止"理论最大损失 > 权益"的头寸。
- **本系统**：断言：任何空头敞口的极端损失（价格翻倍/三倍）必须 ≤ 权益的 X%，否则拒绝下单。

### 13. FTX（2022-11）【F·G】
- **触发链**：关联做市商与交易所资金混同、以自发行代币作为抵押/资产 → 媒体报道其资产负债表 → 竞争对手宣布抛售该代币 → 挤兑 → 收购告吹 → 11-11 破产；据报道客户资金缺口约 80 亿美元量级。创始人 2023 年被定罪、2024 年判刑。
- **根因**：**欺诈**；治理（无独立董事会/审计、储备不可验证）；交易对手方风险被当作"技术风险"忽略。
- **早期信号**：储备依赖自发行代币；无第三方审计/储备证明；关联方做市；高管密集离职；条款被单方面修改；异常关联转账。
- **工程控制**：交易对手敞口上限；储备证明；资产自托管；不以对手方平台币计价保证金；定期提款演练。
- **本系统**：制度 + 断言：单一交易所敞口 ≤ 总权益 X%；月度提款演练；禁止平台币计价抵押（写入 `configs/` 需人工确认）。

### 14. 2024 日元套息平仓（2024-08-05）【C·L·Q·M】
- **触发链**：日本央行 7-31 加息 → 8-2 美国就业数据弱于预期 → 美日利差收窄预期 → 日元急升 → 套息头寸（空日元 + 多风险资产）同时亏损 → 波动率目标策略同步降杠杆 → 夏季薄流动性放大。据报道日经单日跌幅约 12%，创 1987 年以来最大单日跌幅，东证触发熔断，波动率指数盘中冲高。
- **根因**：**相关性突变**（套息 = 空波动率 + 空融资货币，压力下与股票同向）；杠杆；流动性（夏季薄盘）；模型外推（低波动 regime）。
- **早期信号**：日元净空头持仓极端；美日利差预期转向；VIX 期限结构转平；套息类策略与股票相关性上升；央行沟通转鹰。
- **工程控制**：把"融资货币"作为一级风险因子；波动率目标叠加**回撤感知**降杠杆；跨资产相关性压力测试；禁止两条腿同时加杠杆。
- **本系统**：`core/risk/dynamic_allocator.py` 增加"波动率上升 + 回撤"双触发降杠杆；断言：压力情景下相关性矩阵替换为危机矩阵而非历史矩阵。

## 2. 横向模式：四类死法族

| 族 | 案例 | 共同机制 | 唯一有效控制 |
|---|---|---|---|
| **杠杆×流动性螺旋** | LTCM、Archegos、Amaranth、MF Global、2007 地震 | 融资方在最差时点同时抽贷/提保 → 强制平仓 → 价格进一步不利 | 杠杆上限按压力情景 + 预定义减仓阶梯 + 融资集中度监控 |
| **模型外推×相关性突变** | RIEF、2024 套息、Volmageddon、LTCM | 常态估计的关系在压力下失效，"分散"变"同一个头寸" | 危机相关矩阵 + 对冲失效情景 + 因子暴露上限 |
| **运维×发布** | Knight、Flash Crash、负油价 | 一次错误部署/一个未校验假设 → 无界动作 | 原子部署 + pre-trade 限额 + kill switch + 显式领域假设校验 |
| **治理×欺诈** | Barings、MF Global、FTX、Archegos | 同一人/同一实体同时掌握下单、记账、改限额 | 职责与权限分离 + 三方对账 + 独立风控报告线 |

**共同结论**：**所有致死的都不是"信号错了"，而是"错了之后无法停下来"。**
风控系统的目标不是提高胜率，而是保证**单次错误不致命**。【行业共识】
