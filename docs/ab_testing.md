# A/B 测试规程

原则：变量单一、预先声明判据、盲评、小样本不下统计显著性结论。

## 1. Agent 提示词版本对比

- A 为当前版本，B 为候选版本；除被测段落外一字不改，用副本放在 `experiments/` 下，不覆盖 `.github/agents/`。
- 每个版本在同一批用例上各跑至少 3 次（模型有随机性），记录原始输出。
- 评测前写下主指标与通过条件（如 B 的检出率不低于 A 且误报率不高于 A），事后不得更换。
- 评审时隐去版本名；结果整理成 `reports/ab_<name>.json` 后用 `scripts/score_agent_eval.py` 打分。

## 2. causal-guard 检出率

- 用例：`tests/fixtures/causal_guard/c0*.txt`（5 个植入缺陷 + 1 个干净对照），答案键 `answer_key.json`。
- 指标：检出率 = 植入缺陷被判 `FAIL` 的比例；误报率 = 干净对照被判 `FAIL` 的比例；`UNKNOWN` 率单独报告，不计检出。
- 用例只有 6 个，只能发现明显差异；扩大用例集前不要宣称“提升”。
- 用例不得来自静默集，也不得复制真实策略的未公开逻辑。

## 3. 策略/实验变体

- 变体与 `decision_rule` 须在运行前写入并冻结；每个变体运行一次即消耗一次 `trials_N`，由实验脚本登记。
- 对比口径：同数据区间、同成本假设（×1 与 ×2）、同样本外切分；用成对差异与置信区间，不用单次夏普比较。
- 多重检验：按累计 `trials_N` 校正（如 Deflated Sharpe），只报告校正后的结论。
- 禁止因结果不满意而新增变体或改判据；确需新增，作为新试验登记并说明理由。
- 以 `backtest-runner` 执行，结果按其固定模板汇总。
