## 优化概览

### 核心问题
策略编辑弹窗的"我的账户"下拉框为空，无法选择已配置的OKX账户。

### 优化原则
- **第一性原理**：从根问题出发推导，不照搬别人的做法
- **全球最佳实践**：对标Jane Street、Citadel、Binance等顶尖机构
- **最小侵入**：不破坏原有系统，渐进式改进

---

## 问题根因分析

### 五层诊断法

```
Layer 5: UI层       ❌ 下拉框显示"暂无数据"
Layer 4: 过滤层     ❌ compatibleCredentials 过滤后为空
Layer 3: API层      ✅ /api/credentials/list 正常返回数据
Layer 2: 数据层     ✅ 数据库里有OKX凭证
Layer 1: 基础设施  ✅ Docker容器运行正常
```

### 真正的根因

**策略编辑弹窗使用了 `compatibleCredentials` 计算属性，根据策略的市场类型过滤账户：**

```javascript
compatibleCredentials() {
    return this.credentials.filter(s => ft(this.strategyManifest, s.exchange_id))
}
```

**过滤逻辑：**
- 如果策略是Crypto市场 → 只显示加密货币交易所（binance, okx, bitget等）
- 如果策略是USStock市场 → 只显示股票券商（alpaca, ibkr）
- 如果是其他市场 → 什么都不显示

**问题：**
1. 前端过滤逻辑过于严格
2. 用户不知道为什么看不到账户
3. 空状态没有引导信息

## 设计决策记录

### 决策1：为什么不直接修改原有前端？
**理由：**
- 原有前端是编译后的Docker镜像，没有源代码
- 直接修改编译后的JS文件容易出错
- 渐进式改进更安全
- 先做原型验证设计，再考虑完全替换

### 决策2：为什么用三栏布局？
**理由：**
- 这是专业交易终端的行业标准
- Jane Street/Citadel/Binance/OKX全部用三栏
- 经过几十年验证，这是最优布局
- 不要重新发明轮子

### 决策3：为什么把新前端放在/pro/路径？
**理由：**
- 不破坏原有前端的使用
- 用户可以同时访问新旧两个版本
- 对比验证后再决定是否完全替换
- 风险最小
