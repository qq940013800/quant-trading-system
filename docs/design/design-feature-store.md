# 最小特征仓库设计（Feature Store，研究-生产同源）

> 状态：**待评审草稿**，不含生产代码。
> 范围：研究层（`core/`）特征定义、注册表、离线/在线一致性、因果与集合分离、血缘审计。
> 边界：不修改交易/风控/资金逻辑；不触碰 `configs/`、`registry.yaml`、`mt5/`、`secrets/`、`runtime/`、`ledger/`；阈值一律由分布校准，不在本文档拍绩效数字。

## 1. 目标

1. **研究-生产特征同源**：同一特征定义（函数 + 参数 + 输入契约）同时供离线回测/研究与在线推理调用，消除"研究一套公式、线上一套公式"的分叉。
2. **特征定义与注册表**：每个特征登记名称、版本、上游字段、参数、窗口、单位、集合归属（CLEAN 估统计量 / KNOWN 构建区）、`available_at` 口径、代码出处。
3. **离线/在线一致性**：同一 `(symbol, as_of, feature)`，离线重算值与在线计算值可比对；允许登记容差与 NaN 口径，差异必须留痕。
4. **因果与集合分离**：沿用既有 `@as_of` 因果守卫；ATR/波动率/Hurst 等统计量只在 CLEAN 集估计；供需区/结构区只用 KNOWN 集构建；HELD_OUT（静默集）永不进入任何计算输入。
5. **血缘与可审计**：每条决策记录可回溯到当时使用的特征版本、上游数据与取值；特征本身可重算、可复放。

## 2. 现状证据

> 标注口径：**confirmed** = 仓库文件可直接佐证；**inferred** = 由代码路径推断，需进一步核对；**unknown** = 当前快照无法判定。

## 3. 候选方案权衡

| 维度 | A. 代码内注册表（单一函数源，不建物理表） | B. 离线物化特征表 + 在线重算 + 一致性抽检 | C. 完整特征平台（独立在线服务/目录/血缘平台） |
|---|---|---|---|
| 研究-生产同源 | 高：离线在线引用同一函数 | 中：需防物化表与函数脱节 | 高：平台约束，但建设重 |
| 落地成本 | 低 | 中 | 高 |
| 一致性保障 | 靠代码评审与单测 | 有 PIT 抽检任务兜底 | 平台内置校验 |
| 因果守卫复用 | 直接复用 `@as_of` | 复用，物化时同样过守卫 | 需在平台层重建 |
| 血缘/审计 | 元数据挂在注册表条目 | 元数据 + 物化快照双留痕 | 平台血缘模型 |
| 与现有 `core/` 耦合 | 低，贴合现有结构 | 中，需存储与作业 | 高，引入新服务 |
| 在线延迟 | 现场重算，延迟取决于特征复杂度 | 离线表可提供预计算值 | 低延迟 lookup |
| 适用阶段 | 当前最小可行 | 数据基建就绪后 | 规模化后可选 |

## 4. 选型建议（供评审，分阶段）

### 阶段 1：代码内注册表 + 同源收口（优先落地）

- 特征定义集中登记：名称、版本、上游 Bar 字段、参数、窗口、集合归属、`available_at` 口径、作者/代码 commit；注册表条目为纯元数据，不引入新存储。
- 离线面板与在线推理**只允许引用注册表中的同一函数**；先收口 `ml_trend_strategy.py` 内联特征向量，消除第二份实现（inferred 分叉点）。
- 集合归属在注册表里强制标注：统计量类（ATR/vol/Hurst/分位）标 CLEAN；结构/供需区类标 KNOWN；注册时做机检，违反集合分离的条目不予登记。
- 血缘字段挂接现有决策审计记录，可还原"哪笔决策用了哪个特征版本"。

> **落地状态（2026-11-08）**：代码内注册表骨架已落地 `core/features/registry.py`（元数据登记、CLEAN/KNOWN 集合归属机检、同源面板导出、`name@version` 血缘）；离线面板经 `build_feature_panel` 同源收口。在线推理引用、决策审计血缘挂接与内联特征向量去重仍属后续。

### 阶段 2：轻量物化 + 一致性抽检

- 前置依赖：历史 K 线入库（P2-5）就绪后，再物化离线特征快照供研究/回测复用，避免重复计算。
- 增加 PIT 一致性抽检：抽样 `(symbol, as_of, feature)`，比对离线重算与在线值；容差、NaN 口径、缺失窗口在注册表登记；差异写入审计。
- 物化作业同样必须过 `@as_of` 守卫与集合分离校验，不允许旁路取数。

### 阶段 3：在线低延迟 lookup（可选）

- 仅当阶段 1/2 一致性指标稳定、且在线延迟预算证明现场重算不达标时，再评估独立在线特征服务；不在当前阶段引入。

### 不建议

- 先建重型特征平台，再补同源收口。
- 在线侧另写一套特征公式或归一化口径。
- 用全样本分布做归一化/分位（违反 expanding 口径与集合分离）。
- 在无历史数据前提下去物化大规模特征表。

## 5. 未验证假设

- 在线推理延迟预算是否允许阶段 1 的每次现场重算；需在真实 K 线链路（P1-2）接通后度量。
- 现有 Bar 字段能否覆盖拟新增因子（P2-2）所需输入；不足部分需先扩数据层契约。
- 注册表元数据落代码内声明、YAML 还是数据库表，待评审拍板；当前倾向代码内声明 + 审计留痕。
- 离线历史样本长度是否支撑分布校准与一致性抽检，取决于 P2-5 数据导入范围。

## 6. 上线前置条件与验收标准

### 前置条件

- 新特征函数为纯函数：同一 `(history, as_of, params)` 结果可复现。
- 前视守卫单测覆盖每个新特征；集合归属机检可执行。
- 不改动 `configs/`、`registry.yaml`、`mt5/`、风控阈值常量与资金路径。

### 验收标准

1. **同源**：同一特征在离线面板与在线路径指向同一函数；代码核对不存在第二份公式实现。
2. **注册表完整**：每条目含名称、版本、上游字段、参数、窗口、集合归属、`available_at` 口径、出处 commit。
3. **因果**：history 尾部追加未来 bar 后，`as_of` 处取值不变；混入未来 bar 触发 `LookAheadError`（黄金守卫 c01/c02 口径）。
4. **集合分离**：统计量类特征输入仅来自 CLEAN；结构/区域类仅来自 KNOWN；HELD_OUT 不出现在任何计算输入。
5. **一致性**（阶段 2）：抽检样本离线/在线值在登记容差内一致；超差样本有记录与归因。
6. **可审计**：决策记录可还原当时特征取值与特征版本；特征可重算复放。
