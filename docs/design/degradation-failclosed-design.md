# 方案：异常降级 fail-closed 设计——异常场景下「禁新开仓、仅允许平仓」语义

> 状态：**待评审草稿**，不含生产代码、不含强制闸门开关。
> 背景：当前系统对行情源、LLM、数据库、下游交易所四类异常已有各自的局部容错（熔断/重试/缓存/错误分类/预算校验），但**缺少一个跨链路、可审计的全局降级判定**：当关键依赖不可用时，新开仓（open/add）是否被一致拦截、仅允许 reduce/close 退出，尚未在执行链路上收口。本文档只做现状盘点与目标规则设计；强制闸门属交易执行链路判定，与 #107 同类阻塞，本轮不落地代码、不改风控 gate。
> 口径约束：不编绩效数字；所有阈值（熔断窗口、恢复连续成功次数、冷却时长等）均须由 CLEAN/历史分布校准或运维基线确定，禁止按回测 PnL 网格搜索产生（对齐 AGENTS.md 不变量 3「阈值来自分布」）。

## 1. 目标

### 1.1 第一性原理
- 生存优先：异常态下任何新开仓都缺少可靠的价格、仓位、对手方或账户状态支撑，继续入场属于在信息不全时下注；平仓/减仓是降低风险敞口的动作，应被保留。
- fail-closed（默认拒绝）：关键依赖不可用或状态不可判定时，默认拒绝新开仓；只有在依赖健康度可证实恢复、且通过既有风控校验后，才解除新开仓限制。
- 决策可审计：每一次进入/退出降级态、每一笔被拦截的新开仓、每一笔被放行的平仓，都能还原触发来源、判定依据、时间戳与人工操作记录（对齐不变量 2）。
- 因果单向：降级判定只使用 `available_at <= 当前 bar.close` 之前可观测到的健康信号，不得用未来 bar 推断依赖已恢复（对齐不变量 1）。

### 1.2 目标语义（待评审）
| 状态 | 新开仓（open_long/open_short/add_long/add_short） | 平仓/减仓（close_long/close_short/reduce_long/reduce_short） |
|---|---|---|
| NORMAL（依赖健康，判定可证实） | 允许，仍须通过既有风控/预算/方向模式/持仓归属校验 | 允许 |
| DEGRADED（任一关键依赖处于异常或不可判定） | **拦截**，记录拒绝原因，不产生新仓位 | **允许**（reduce-only 退出链路保留），仍须通过仓位归属与订单参数校验 |
| RECOVERING（异常后观察窗口内） | 拦截或受限（见 §4 恢复条件，供评审二选一） | 允许 |
| MANUAL_HOLD（人工挂起） | 拦截 | 按人工指令，默认允许平仓 |

### 1.3 非目标（本轮明确不做）
- 不写「禁新开仓/仅平仓」的强制闸门代码，不接入下单链路，不改既有风控 gate、止损、仓位/资金计算。
- 不修改 `configs/`、`registry.yaml`、`mt5/`、`secrets/`、`runtime/`、`ledger/`；不改数据库 schema。
- 不定义任何绩效承诺、收益数字；不把机构数值照搬到本系统。

### 2.5 现状缺口小结（供 §3 选型对照）

- 四类依赖各有局部容错，但缺少统一健康度聚合与降级状态机；异常信号散落在返回空、返回 0、返回默认结构、抛错、日志 Warning 等不同出口。
- 现有闸口都是**单笔/单策略校验**（持仓归属、预算、方向模式、信号字段、AI 单决策），没有跨依赖的「全局可否新开仓」判定。
- 行情报价异常被降级为 `last=0`（M2），存在以零价参与后续计算的风险；DB/交易所异常对开仓链路的传导路径未收口。
- 审计上：单笔拒绝已有归属/预算/方向理由，但缺少「进入/退出降级态」本身的状态变更记录与人工恢复留痕。

## 3. 候选方案权衡

> 以下方案为评审选型，均不代表本轮落地；阈值类参数一律待分布/基线校准。

### 3.1 候选方案

| 维度 | A. 依赖健康度状态机（集中式降级闸） | B. 各依赖就地 fail-closed（调用点各自拒绝开仓） | C. 观察面板 + 人工闸门（先只观测不拦截） |
|---|---|---|---|
| 思路 | 聚合行情/LLM/DB/交易所健康度，输出 NORMAL/DEGRADED/RECOVERING/MANUAL_HOLD，新开仓统一过闸 | 每个依赖调用点在异常时直接返回「不可开仓」，平仓路径不经过该拒绝 | 先把四类健康信号上屏/落库，人工观察一段时间，再决定是否自动拦截 |
| fail-closed 强度 | 高：单一判定源，异常/不可判定默认拒绝开仓 | 中：依赖各点独立，口径易不一致，漏判风险分散 | 低：仅提示，不拦截，异常态仍可能开仓 |
| 与现有代码契合 | 复用 M3 熔断器、X1 错误分类、X5/X6/X7 既有闸口作为信号源；新增聚合层 | 改动分散到各数据源/服务/客户端，重复判定多 | 改动最小，只读观测为主 |
| 审计可还原 | 状态变更、放行/拦截、人工操作集中留痕 | 拒绝理由分散在各调用点，还原链路长 | 只有观测记录，无拦截决策留痕 |
| 误杀风险（健康抖动导致停开仓） | 需抖动抑制：连续成功/失败窗口、冷却与去抖，阈值待校准 | 单点抖动即拒绝，误杀面可能更广 | 无误杀，但也无保护 |
| 恢复可控性 | 状态机显式 RECOVERING 观察窗 + 人工复核入口 | 各点自行恢复，全局恢复时点不一致 | 人工凭观察恢复 |
| 工程复杂度 | 中高：状态机 + 信号采集 + 审计 + 与执行链路对接（对接属 #107 同类阻塞） | 中：改动点多但单点逻辑简单 | 低：观测与展示为主 |
| 主要风险 | 状态机自身成为单点；健康信号定义不当导致误判/漏判 | 口径漂移；平仓/开仓在调用点难一致区分 | 真实风险暴露期内仍在开仓 |

### 3.2 关键设计抉择（评审拍板项）

- **S1 判定位置**：集中式（A）还是分散式（B）。集中式利于口径一致与审计，分散式利于渐进改动；本设计倾向 A 作为目标态，C 作为前置观测阶段。
- **S2 哪些依赖纳入「禁开仓」判定**：
  - 行情源：价格/最新 K 线不可靠时，新开仓缺入场价与触发依据，建议纳入。
  - DB：持仓归属/预留/审计写不下去时，新开仓缺可核对的仓位事实，建议纳入（只读快照类查询不强制纳入）。
  - 交易所：下单通道或账户状态查询不可用时纳入；纯行情所与交易所需区分。
  - LLM：若 LLM 不直接产生开仓信号（见 L6 待核对），LLM 不可用应只降级分析/复盘，**不应单独触发禁开仓**；是否纳入取决于 L6 结论。
- **S3 不可判定时的默认值**：健康度无法证实（超时、信号缺失、状态未知）按 fail-closed 计为 DEGRADED，还是按 NORMAL 放行。目标倾向不可判定 → DEGRADED（拒绝开仓）。
- **S4 平仓在异常态的保障**：DEGRADED 下 reduce/close 放行；若平仓通道本身也不可用（交易所/DB 同时故障），如何保证退出不被新增闸口二次阻塞，需评审明确。
- **S5 RECOVERING 窗口语义**：恢复后先观察若干个连续健康样本（窗口长度待基线校准）才回到 NORMAL；观察窗内是继续禁开仓，还是允许受限开仓。

## 4. 分阶段选型建议（供评审）

### 阶段 0：只读观测（C，可先行，不碰执行链路）
- 采集四类依赖健康信号：行情成功率/报价有效性、DB 池与心跳、交易所连通性与错误分类、LLM 可用性（仅分析路径）。
- 记录信号时间序列与既有单笔拒绝原因，不上屏演示数字，缺值 `--`；不新增拦截动作。
- 产出基线：各依赖在正常/抖动/故障下的分布，作为后续窗口与阈值校准依据（禁止按 PnL 反推）。

### 阶段 1：集中式状态机设计与离线评审（A 的设计部分，不接下单）
- 定义状态枚举、输入信号、转移条件、去抖/冷却规则、审计字段；用既有 `ResourceExhaustedError`、错误分类、持仓归属/预算/方向闸作为信号源。
- 离线/回测环境用历史故障样本演练状态转移；**不在实盘下单链路挂强制闸**。
- 明确 S1–S5 拍板结论，形成可实现的接口契约（状态查询、拒绝理由、审计写入点）。

### 阶段 2：强制闸门落地（阻塞项，待 #107 同类拍板后另立任务）
- 经评审与人工确认后，在执行链路引入集中降级闸：DEGRADED/RECOVERING/MANUAL_HOLD 拦截 open/add，放行 reduce/close。
- 对接既有风控 gate 与订单意图构建处；配套单测（状态转移、异常/不可判定默认拒绝、平仓放行、审计留痕）；黄金集断言不放宽。
- 上线前在 demo/最小手数验证，实盘冒烟与经纪商差异属未验证项，单独标注。

### 不建议
- 在健康度信号未基线化前，直接用拍脑袋的固定阈值（次数/秒数）上线自动禁开仓。
- 让 LLM 分析故障单独触发交易级禁开仓（除非核对到 LLM 直接产出开仓信号）。
- 用行情异常返回的零价 `last=0` 参与入场名义/仓位计算而不标注数据不可用。

## 5. 目标降级规则设计（阶段 2 落地参考，本轮不写代码）

### 5.1 状态判定输入信号
| 信号源 | 健康判定参考（阈值待校准） | 现有可复用证据 |
|---|---|---|
| 行情 | 最近窗口内 K 线成功获取率、报价 `last>0` 且非陈旧、定向源未跨所回退 | M1/M2/M5/M6 |
| DB | 池获取未超时、关键读写成功、worker 心跳新鲜 | D1/D2/D3 |
| 交易所 | 账户/持仓查询与下单通道连通；错误分类非持续 transport/配置类 | X1/X2/X8 |
| LLM | 仅当核对到其参与开仓信号时纳入；否则仅记录分析可用性 | L1–L6 |

### 5.2 状态转移（目标态）
- NORMAL → DEGRADED：任一纳入依赖进入故障态，或健康信号不可判定（超时/缺失/未知）。
- DEGRADED → RECOVERING：故障依赖连续若干个健康样本（窗口待基线校准），无新的致命错误。
- RECOVERING → NORMAL：观察窗内持续健康且无未恢复告警；RECOVERING → DEGRADED：观察窗内再次出现故障信号。
- 任意状态 → MANUAL_HOLD：人工挂起；MANUAL_HOLD → 需人工解除并复核。
- 去抖：短抖动不立即翻态；连续失败/成功计数与冷却时长由历史分布与运维基线确定。

### 5.3 降级期交易许可
- 拦截动作：`open_long / open_short / add_long / add_short`。
- 放行动作：`close_long / close_short / reduce_long / reduce_short`（reduce-only）。
- 放行的平仓仍须通过既有仓位归属、手数精度、订单参数校验；新增降级闸不得成为平仓退出的二次阻塞点。
- 被拦截的新开仓：不生成新仓位意图，记录拒绝状态、触发依赖、判定时点与依据信号。

### 5.4 恢复条件
- 技术恢复：所有纳入依赖回到健康样本窗口内，DB 可读写归属/预留/审计，交易通道可查询账户状态。
- 人工复核：DEGRADED 持续超过设定时长（待校准）或状态从故障转恢复时，需人工确认依赖根因已排除；MANUAL_HOLD 必须人工解除。
- 恢复后不自动补开降级期间错过的信号；新信号按恢复后当前行情重新评估（因果单向，不回填历史触发）。

### 5.5 审计记录字段（目标契约，不改现有 schema）
- 状态变更：状态 from/to、触发依赖、信号快照、时间戳（服务端时间，时区与 `--tz` 对齐）、触发方式（自动/人工）。
- 单笔拦截：策略、品种、动作、信号时间、降级状态、拒绝理由码、关联订单意图/决策 key。
- 人工操作：操作人、动作（挂起/解除/放行例外）、备注、时间戳。
- 审计口径与既有决策/交易日志一致；缺字段不编造，未知记 `--`/unknown。

### 5.6 人工恢复路径
- 观测：只读面板/日志查看各依赖健康与当前降级状态（阶段 0 起可建）。
- 挂起/解除：人工可置 MANUAL_HOLD、解除挂起；解除前核对依赖根因与持仓敞口。
- 例外放行：是否允许在 DEGRADED 下人工批准单笔新开仓，属风控策略决策，需评审；默认不提供旁路绕过。

## 6. 未验证假设

- A1：LLM 不直接产出进入下单链路的开仓信号（L6 未逐一路径核对）；若实际存在，则 LLM 故障应纳入禁开仓判定。
- A2：行情 `last=0` / 空 K 线目前未被下游当作有效价格参与开仓计算（M2/M8 未在执行链路实测）。
- A3：DB 短时不可用时，既有读写会抛错并被上层记录，不会静默放行未核对仓位的开仓（D4 为推断）。
- A4：交易所 transport 类错误当前只影响单笔重试，未造成在故障态持续派发新开仓（X8 为推断，需实盘/演练验证）。
- A5：阶段 0 采集到的健康样本足以支撑去抖窗口与冷却时长校准；样本不足时相关阈值保持未知，不拍固定值。
- A6：worker 心跳 45s stale 口径可作为 DB/进程健康的参考信号，但不等同于交易所或行情健康。

## 7. 上线前置条件与验收标准

### 7.1 前置条件（阶段 2 强制闸门前必须满足）
1. L6 核对完成：明确 LLM 是否参与开仓信号；S1–S5 经评审拍板并留档。
2. 阶段 0 健康基线已采集，去抖/恢复窗口/冷却阈值由分布或运维基线确定，未用绩效网格搜索。
3. 降级闸与既有风控 gate、订单意图构建、持仓归属/预算/方向校验的对接点完成设计评审；与 #107 同一阻塞口径对齐。
4. 审计字段与既有决策/交易日志口径对齐；不改既有 schema（新表/新字段另走变更评审）。
5. demo 账户最小手数演练：故障注入（行情空/DB 断/交易所 5xx）下拦截开仓、放行平仓、状态转移与审计留痕符合预期。

### 7.2 验收标准（阶段 2，落地后核对）
- V1：纳入依赖故障或不可判定时，open/add 被拦截并记录理由；reduce/close 不被新闸阻塞。
- V2：状态转移（NORMAL/DEGRADED/RECOVERING/MANUAL_HOLD）有完整审计记录，可还原触发来源与时间戳。
- V3：恢复需满足连续健康样本窗 + 必要人工复核；恢复后不回填历史信号。
- V4：不可判定状态默认拒绝开仓（fail-closed），不存在默认放行分支。
- V5：单测覆盖状态转移、异常/未知默认拒绝、平仓放行、审计写入；黄金集断言未放宽。
- V6：不修改下单/资金/止损/风控既有计算；降级闸只做许可判定与记录。
- V7：实盘冒烟、经纪商差异、故障注入在真实环境的表现标注「未验证」，不以内测结果替代。
