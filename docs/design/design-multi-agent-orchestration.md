# 多 Agent 职责与编排规范（草案）

> 状态：待评审草稿；对齐 `docs/knowledge/08_system_blueprint.md` §7 上线门禁、`docs/design/architecture-optimization-roadmap.md` 分层与 `AGENTS.md` 红线。
> 本规范定义项目内四个工程角色的职责边界、交接契约与门禁放行条件；不替代蓝图与 ADR，冲突时以三不变量、蓝图门禁与 AGENTS.md 为准。

## 1. 定位与非目标

- **角色即职责切面**：下文的“Agent”是工程角色与职责划分，不是常驻后台自治交易员。当前执行环境只能在会话内委派编排 Agent（Organizer），会话结束即终止；不存在 7×24 常驻、自动下单的自治进程。
- **不承诺盈利**：期望收益 = Edge(统计边际) × 暴露(仓位/时长) × (胜率×均盈 − 败率×均亏) − 交易成本 − 尾部回撤。只有通过上线门禁后，才可按「影子 → 小资金 → 全量」灰度推进；研究阶段不标注任何“可上线/盈利”结论。
- **三不变量优先于任何角色目标**：① 因果单向（只用 `available_at <= bar.close` 的数据）；② 决策可审计（每笔接受/拒绝可还原各层输入与判断）；③ 阈值来自分布（不由绩效网格搜索产生）。

## 3. 各角色职责与交接契约

### 3.1 ORCH 项目负责人
- 把目标拆成可验证切片，按 P0/P1/P2 与蓝图 G1–G13 排序；维护 TODO 单一事实源，不另写一套待办。
- 评审研究证据是否满足门禁；把关交接物完整性、口径一致性与可审计性。
- 识别红线触发（`configs/`、`registry.yaml`、`mt5/`、风控阈值、实盘资金路径）即停下转人工，不自行推进。
- **输入**：用户目标、蓝图、TODO、ADR。**产出**：切片清单、交接验收结论、门禁放行/驳回记录。

### 3.2 RES 策略研究 Agent
- 提出可证伪假设，构造特征/信号/状态识别；严格保证因果单向，前视数据不得进入特征/区域/统计量。
- 跑 purged walk-forward、CPCV、PBO、DSR 与成本×1.5 压力测试；登记 trials 账本；决策规则在实验前冻结，禁止事后改写。
- 阈值从 CLEAN/KNOWN 训练分布分位校准，禁止按绩效网格搜索切点；ML 只承担 L2 状态权重、L3 meta-labeling 过滤、概率→仓位映射，**不生成方向**。
- **交接给 ENG 的产物**：策略/信号规格、输入输出契约、样本外证据摘要、需要固化的参数边界。
- **边界**：不写生产服务代码；不落地实盘下单；结论未过门禁不得标注可上线。

### 3.3 ENG 代码实现 Agent
- 按研究规格把纯函数、服务、路由、适配器、前端落地；复用既有测试接缝；附或更新单测，不放宽黄金集断言。
- 在边界处做类型/有限性/区间校验；异常带上下文记录，禁止 `except Exception: pass`。
- 保持模块边界：`services` 不含 Flask request 对象（仅路由边界接触），适配器不混策略生命周期与用户鉴权（对齐 `docs/architecture/MODULE_BOUNDARIES.md`）。
- **交接给 RISK/ORCH 的产物**：可运行代码、测试结果、AST/回归记录、已知未验证项。
- **边界**：不改研究假设；不调风控阈值；不碰 `secrets/`、`runtime/`、`ledger/`、`configs/`、`registry.yaml`、`mt5/`；不删除任何文件。

### 3.4 RISK 仓位资金管理 Agent
- 所有仓位以「每笔风险占权益比例」为唯一单位，可加总、可限额、可熔断。
- 以单笔止损 + 仓位硬约束约束下行；维护组合相关性、回撤分级降档、动态分配与压力测试约束。
- 对账以 fill 成交记录为准，不用滞后余额反推单笔盈亏；现货平仓前先核准钱包真实基础币余额，防超卖存量。
- **交接物**：风险约束参数边界、仓位映射规则、熔断/降档触发条件、对账口径。
- **边界**：不决定方向、不生成交易信号；不绕过风控放大敞口；风控阈值常量不擅改（需人工确认）。

## 4. 协作流程（因果顺序）

1. 假设（RES）→ 2. 研究证据与样本外初筛（RES）→ 3. 工程实现与单测（ENG）→ 4. 风险约束装配（RISK）→ 5. ORCH 门禁评审 → 6. 影子运行 ≥4 周 → 7. 小资金灰度 → 8. 全量；每步可回滚。

策略因果顺序固定为 L1 位置 → L2 状态 → L3 触发；禁止 L3 结果反哺 L1 定义。跨角色交接必须带可复核输入与结论，不允许“实现存在即视为生产激活”。

## 5. 门禁放行条件（引用蓝图 §7）

| 指标 | 通过线 | 说明 |
|---|---|---|
| PBO | < 0.5（警告 0.3） | 组合对称交叉验证，越低越好 |
| Deflated Sharpe | > 0（95% 置信更佳） | 已按 trials 修正 |
| CPCV 方向一致率 | ≥ 60% | CPCV 底座修好后启用 |
| 成本×1.5 后期望 | > 0 | 保守成本压力 |
| 样本外交易数 | ≥ 100 笔（或统计功效达标） | 大数定律 |
| 影子运行 | ≥ 4 周 | 实盘行情、模拟下单 |
| 回放校验 | 100% 一致 | Decision 五要素 |

任一指标不过：驳回回 RES/ENG，不得进入影子或小资金阶段。

## 6. 红线与停止条件（对齐 AGENTS.md）

- **禁改**：`secrets/`、`runtime/`、`ledger/`；`mt5/` 风控阈值常量；`configs/`、`registry.yaml`。
- **需人工确认**：`configs/`、`registry.yaml`、`mt5/`、风控阈值、实盘资金路径、多标的/多周期扩容。
- **触发即停并转人工**：连续两次测试失败；需删文件/改数据库/碰实盘资金路径；疑似未来函数无法判定；需读静默集或扩大数据范围。
- LLM 只做研究/运维文本处理，输出落到文件/测试/PR 并人审，**禁止进入下单路径**。

## 8. 执行环境与委派说明

- 会话内由 ORCH（MainAgent / OrganizerAgent）按切片委派 RES/ENG/RISK 角色子任务；角色是任务切面，不持有独立持久状态，会话结束即释放。
- 每次改动按 AGENTS.md 输出四件事：改了哪些文件 / 为什么 / 跑了什么验证 / 剩余风险；无法自动验证的项（实盘冒烟、经纪商差异等）显式标注「未验证」。
- 本规范为组织协作约定，不引入新依赖、不改变既有代码行为；后续切片落地时若与现有蓝图/ADR 冲突，回到 ORCH 评审后再改。
