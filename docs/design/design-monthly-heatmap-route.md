# 方案 3：月度收益热力图路线选型——【后端预聚合】vs【前端 equityCurve 按月切片】

> 状态：**待评审草稿**，不含生产代码。
> 背景：回测页月度热力图当前为 12 格静态演示数字（+3.2 / +5.1 / -1.8 …）。后端**无月度收益分布接口**；回测详情 `result.equityCurve` 为日级权益序列（实测 id=9 约 1200 点，每点 `{time: ISO, value, cash, grossExposure, netExposure, drawdown}`）。

## 1. 热力图需要的数据

- 行：年份；列：1–12 月；格值：该月收益率（百分数，正绿负红）。
- 单策略单回测：至少给出覆盖区间内各月收益；多年份需年份×月份矩阵。
- 口径：月度收益 = 月末权益 / 上月末权益 - 1（首个月按月初权益起算）；须与权益曲线口径一致。

## 2. 两条路线

### 路线 A：后端预聚合月度收益

**做法**
- 后端在回测完成/查询时，基于权益曲线（或成交记录）按年月聚合月度收益，返回结构化矩阵：
  ```json
  { "code": 1, "data": { "monthly_returns": [ {"year": 2026, "month": 11, "return": 4.85} ], "as_of": "..." } }
  ```
- 前端只负责渲染颜色与 `--` 空态，不做收益计算。

**优点**
- 计算口径集中在后端，前端/多端（Web、后续移动端）结果一致；便于单测覆盖聚合逻辑。
- 前端轻，不随点数增长做浏览器侧计算；可做跨策略、跨回测的月度对比。
- 聚合规则（月初/月末取点、首月口径、空月处理）可在后端固化并写测试。

**缺点**
- 需新增接口或在回测详情里补充 `monthly_returns` 字段；依赖后端改动与单测。
- 实时/增量回测下，未走完月份的月度收益口径需额外定义（截至当日 vs 月末）。

### 路线 B：前端 equityCurve 按月切片聚合

**做法**
- 前端拉取 `equityCurve` 日权益点，按 ISO 时间归到年月，取每月末（区间最后一点）权益与上一月末权益，计算月收益后渲染。

**优点**
- 不依赖后端新接口，复用已可达的权益曲线；落地快。
- 适合单回测、单视图的快速展示。

**缺点**
- 收益计算分散在前端，多端口径易漂移；浏览器侧需处理时区、缺月、首月、重复时间戳等边界。
- 权益曲线点数大（千点级）时前端切片排序；多次进入回测页重复计算。
- 无法直接支撑跨策略/跨回测的月度汇总（需前端再拉多条曲线）。
- 聚合逻辑缺自动化单测（当前仓库无 JS 测试基建），正确性只能人工核对。

## 3. 对比表

| 维度 | A 后端预聚合 | B 前端切片 |
|---|---|---|
| 计算位置 | 后端 | 浏览器 |
| 口径一致性 | 高，集中固化 | 低，多端易漂移 |
| 落地速度 | 需后端接口+单测 | 复用现有曲线，较快 |
| 前端负担 | 轻 | 中（排序/归月/边界） |
| 可测试性 | 后端单测可覆盖 | 无 JS 测试基建，靠人工 |
| 跨策略/多年份 | 易扩展 | 需前端多拉多算 |
| 时区/缺月边界 | 后端统一处理 | 前端各自处理，易漏 |
| 数据复用 | 可被看板/报表复用 | 仅当前视图 |

## 4. 选型建议（供评审）

### 推荐：路线 A（后端预聚合）为主
- 热力图是绩效分析产物，口径应与回测引擎、绩效快照（见方案 1）一致；聚合规则落后端并附单测。
- 先在回测详情接口补充 `monthly_returns`（年/月/收益），前端按矩阵渲染；空月/无数据格 `--`。

### 过渡：路线 B 作为短期兜底（可选）
- 若后端接口排期靠后，可先用前端切片在单回测视图过渡，但须在代码与 UI 标注"前端聚合，口径待后端固化"，且边界处理（时区、缺月、首月、重复戳）写清。
- 过渡期内不得把前端聚合结果当作跨策略汇总口径。

## 5. 未决项（评审拍板）

- **D1 月度收益基准**：以上月末权益为基准；首月以月初（初始资金）为基准；未走完月份按截至当日权益还是留空。
- **D2 时区归属**：月按交易所/UTC 还是本地时区切分；跨时区交易日归属规则。
- **D3 多年份矩阵**：当前回测跨度多年（实测 2018–2026），热力图是否按年份分行展示，还是只展示最近 12 个月。
- **D4 与权益曲线口径对齐**：月度收益是否用 `value`（权益）还是净值口径；扣费/ funding 已在权益曲线内反映后不再重复扣。
- **D5 无成交/无信号月份**：收益记 0、`--` 还是标注 `no_signals`。

## 6. 验收标准（路线 A）

1. 接口返回结构化月度收益；前端空月/无数据渲染 `--`，不出现静态演示数字。
2. 月度收益口径在后端固化并附单测；首月、缺月、未走完月份边界有断言。
3. 与权益曲线、绩效快照口径一致；不修改交易路由、风控 gate、下单/平仓与资金计算。

## 7. 风险与未验证

- 当前 equityCurve 为日级点，若部分回测粒度非日（如小时线），月度聚合需先降采样到日权益，规则待定。
- 本方案未落地；接口字段与聚合窗口需在实现前与回测引擎权益口径复核。
