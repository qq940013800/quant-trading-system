## 技术债与经验教训（必须沉淀到知识库）

### 前端拆分踩坑经验
1. **禁止用PowerShell处理UTF-8中文文件**：Get-Content/Set-Content会搞坏编码，导致JS语法错误（字符串没闭合）
2. **前端文件修改后必须用Node.js做语法检查**：`node --check app.js`，通过了再部署
3. **Docker部署后必须强制刷新浏览器**：浏览器会缓存旧的JS/CSS，导致改了不生效
4. **拆分前必须备份原始文件**：拆分失败能快速回滚
5. **禁止用固定行号拆分前端**：行号一变就错，应该用正则匹配 `<style>`/`<script>` 标签
6. **拆分后必须检查残留标签**：JS文件里不能有 `</script>` 或 `<script>` 标签残留

### 后端开发踩坑经验
1. **Python方法名必须和调用方严格一致**：每次改服务层方法，都要检查路由层的调用
2. **Docker容器代码不是挂载的**：本地改完必须docker cp进去，重启容器才生效
3. **Blueprint路由不能带url_prefix**：统一在register.py注册时传
4. **函数命名不一致是最高频bug**：前端 `logDebug` vs `debugLog` 这种小问题会导致整个JS执行中断

### 部署与运维踩坑经验
1. **浏览器缓存是前端调试最大敌人**：每次部署后必须 `ignoreCache: true` 强制刷新
2. **Docker容器内文件修改后不会自动同步**：必须手动 docker cp
3. **Git分支名要统一**：gitee用main不是master，避免推送报错
